# 路径可分片 ID 与可伸缩性审视（NFR 硬门禁附录）

> 被 `/5-nfr` 强制引用。元规则 SSOT：`.ai/01_project_constraints/48_nfr_path_shard_id_scalability.md`。

## 适用范围（「路径」定义）

对当前增量涉及的每一条寻址路径做审视，包括但不限于：

| 路径类型 | 示例 |
|----------|------|
| HTTP/API | `/api/v1/tenants/{tenantId}/members`、`/api/v1/members` |
| 前端路由 | `/tenant/:tenantId/people/manage`、`/admin/users` |
| 消息路由键 | Kafka key、消费分区键、事件 envelope 中的路由字段 |
| 存储/缓存键前缀 | Redis key、对象存储前缀（若作为水平扩展边界） |

**可分片 ID**：可用于水平分片/分区的业务键（常见：`tenant_id` / `company_id`、必要时 `workspace_id`）。须与冷热分离/分片元规则中的「伸缩要素」对齐。

## 决策树（强制）

```
对增量中每条路径：
│
├─ 路径上是否携带可分片 ID？
│   │
│   ├─ 否 → 【无分片 ID 分支】必须回答：
│   │         1. 该路径触及的数据/流量是否有可伸缩性需求？（L0–L4）
│   │         2. 若有（≥ L1）：缺少分片键会如何阻碍扩容？补救方案是什么？
│   │            （补路径参数 / 强制查询带 shard key / 接受单分片全局索引并写明上限）
│   │         3. 若判定无伸缩需求（L0）：须写明理由与升级触发条件（不可空话跳过）
│   │
│   └─ 是 → 【有分片 ID 分支】必须回答：
│             1. 该 ID 是否为合适的分片键？（见下方适配性清单）
│             2. 不适配时：正确分片键应是什么？路径/事件键如何改？过渡策略？
│             3. 适配时：确认常见查询/写路径是否总能带上该键（禁止跨分片默扫）
```

## 无分片 ID：何时仍可标 L0

仅当**同时**满足时可标可伸缩性 L0（仍须写入文档）：

- 预期数据量与 QPS 在可预见窗口内单实例可承受；且
- 路径为低频管理/运维/只读目录类；且
- 写明升级触发（如「单表 > 100 万行或 P95 > 目标」时必须引入分片键）

禁止：「暂时不管」「以后再说」作为跳过理由。

## 有分片 ID：适配性清单

逐项勾选；任一「否」则判定为**不合适分片 ID**，须在 NFR 文档记录并给出纠正动作：

| # | 问题 | 期望 |
|---|------|------|
| 1 | 高基数且分布相对均匀？ | 避免按低基数字段（status/type）分片 |
| 2 | 与 90%+ 读写访问模式对齐？ | 列表/详情/事件消费常带该键 |
| 3 | 支撑租户（或等价）隔离？ | 多租户场景优先 `tenant_id` 类，而非裸 `user_id`/`member_id` |
| 4 | 稳定、变更极少？ | 分片键不宜随业务频繁迁移 |
| 5 | 不会制造热点或强制扇出？ | 避免「全局热实体 ID」导致单分片过热 |
| 6 | 与表分区/库分片策略一致？ | 与 `database-cold-hot-separation` 伸缩要素一致 |

### 典型判定

| 路径中的 ID | 通常判定 | 说明 |
|-------------|---------|------|
| `tenantId` / `companyId` | 合适（多租户默认） | 与租户分库/分片天然对齐 |
| `workspaceId`（租户内） | 视场景 | 可作为二级键；单独作全局分片键需证明访问模式 |
| 仅 `memberId` / `userId` | 常不合适作租户级分片 | 跨租户查询与隔离困难；宜同时带 `tenantId` |
| 仅 `taskId` 且主查询按租户列表 | 常不合适作唯一分片键 | 列表会跨分片；宜 `tenantId`(+`taskId`) |
| 枚举/状态段 | 不合适 | 低基数 → 倾斜 |

## NFR 文档必写小节

每个增量的 NFR 澄清文档须含：

```markdown
## 路径分片键审视

| 路径 | 分片 ID | 判定 | 可伸缩性等级 | 结论 / 动作 |
|------|---------|------|-------------|-------------|
| GET /api/.../members | 无 | 缺键 | L2 | 须在路径或强制 query 增加 tenantId；否则无法按租户扩容 |
| /tenant/:tenantId/... | tenantId | 合适 | L2 | 聚合根与仓储查询必须携带 tenant_id |
```

跳过整节 → Hard Gate 失败。

## 与领域模型的衔接（喂给 /6-ddd）

| 审视结论 | DDD 动作 |
|----------|---------|
| 无键且需要伸缩 | 聚合根补分片键字段；API/事件契约补键；禁止无键全表扫描用例 |
| 键不合适 | 改聚合身份/仓储接口以正确分片键为必参；路径/Topic key 对齐 |
| 键合适 | 仓储所有查询签名包含分片键；跨分片用例显式列为反模式 |
