# Loop — 定时循环执行

## 调度机制（强制 — 本轮结束时必须执行）

> **间隔 ≠ 执行时限**：间隔只控制本轮完成后的**等待时长**，不限制本轮实际执行时间。
> 每轮可以执行任意长的任务——即使本轮实际工作了 3 分钟，2m 间隔也只是再等 2 分钟后继续下一轮。
> **禁止因"剩余工作量大"或"单轮耗时长"而停止循环。**

**仅输出时间戳文本不会触发下一轮** — 必须在时间戳区块输出后，调用 `CronCreate` 实际创建定时任务。

### 首次执行（用户直接调用 `/loop`）

1. 解析参数：间隔（默认 10m）+ 子命令
2. 执行子命令（本轮内联执行）
3. 输出时间戳区块（含下一轮时间）
4. **调用 `CronCreate`** 创建定时作业：

```
CronCreate(
  cron=<从间隔推导的 cron 表达式>,
  prompt="/loop <原始间隔> <原始子命令>",  // 重新触发自身
  recurring=true,
  durable=false  // 会话级，重启后消失
)
```

**间隔→cron 推导规则**：
- `Nm`（N 分钟）：避开 :00/:30 尖峰，分钟取 `N % 30 + 3` 偏移。如 `10m` → `3,13,23,33,43,53 * * * *`
- `Nh`（N 小时）：`7 */N * * *`（避开整点）
- 默认 10m：`3,13,23,33,43,53 * * * *`

### Cron 触发执行（定时作业唤醒）

1. 收到 cron 唤醒 → 识别为 /loop 续轮（非用户手动触发）
2. 执行子命令
3. 输出时间戳区块（含下一轮时间）
4. **不重复创建** CronCreate（作业已存在，自动续期）

## 时间戳标注规则（强制）

每一轮循环的输出末尾，**必须**附带本轮时间戳区块，格式如下：

```
---
⏱️ **本轮时间戳**
- 开始时间: `2026-07-25 14:32:05 CST`
- 完成时间: `2026-07-25 14:32:18 CST`
- 下一轮: `2026-07-25 14:42:05 CST`（间隔 10m）
```

### 获取时间的方法

在每轮开始时执行 `date '+%Y-%m-%d %H:%M:%S %Z'` 获取开始时间，完成本轮输出前再次执行获取完成时间。

### 下一轮时间计算

根据用户指定的间隔（默认 10m），在开始时间基础上加上间隔推算下一轮开始时间。使用 `date -d '+10 minutes' '+%Y-%m-%d %H:%M:%S %Z'` 计算。

### 示例

用户执行 `/loop 5m /status`，每轮的输出应如下：

```
[执行 /status 的结果...]

---
⏱️ **本轮时间戳**
- 开始时间: `2026-07-25 14:30:00 CST`
- 完成时间: `2026-07-25 14:30:12 CST`
- 下一轮: `2026-07-25 14:35:00 CST`（间隔 5m）
```

### 示例：长任务 + 短间隔

用户执行 `/loop 2m /goal 执行大规模迁移`，某轮耗时约 3 分钟：

```
[执行迁移任务，本轮完成 3 个端点迁移...]

---
⏱️ **本轮时间戳**
- 开始时间: `2026-07-25 14:30:05 CST`
- 完成时间: `2026-07-25 14:33:12 CST`（本轮工作了 ~3 分钟）
- 下一轮: `2026-07-25 14:35:12 CST`（再等 ~2 分钟空闲）
```

即使本轮耗时远超间隔，循环仍然继续——间隔只影响**完成后**的等待时间。

## 停止条件

循环仅在以下情况主动停止：

- 用户明确发送 `stop` / `停` / `取消` / `结束循环`
- 目标 100% 完成（所有可执行优化项均已关闭）
- 连续 **3 轮**无任何实质性产出（死循环检测——每次 cron 唤醒后确实无工作可做）

**禁止因以下理由停止**：
- "剩余工作量大，不适合当前间隔" — 间隔不限制执行时间
- "单轮耗时超过间隔" — 间隔只控制等待，不控制工作时长
- "需要用户确认" — goal-mode 全程零交互，自主决策
