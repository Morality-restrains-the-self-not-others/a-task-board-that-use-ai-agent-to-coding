# 设计：分支策略「目标分支」展示共有分支

## 背景

任务详情「分支策略」编辑态中，「目标分支」目前依赖硬编码模板（develop / main / release / custom），与仓库真实分支无关。合并目标必须是关联仓库中已存在的分支；多仓库时只能选各仓**共有**分支名。

## 成功标准

1. 进入编辑（或关联项目/仓库变化）时，对任务关联项目下**全部** Git 仓库拉取分支列表（复用既有 `GET …/projects/{id}/branches/?repo_url=`）。
2. 目标分支下拉选项 = 各仓库分支名的**交集**（排序后展示）。
3. 加载中有提示；无共有分支时可选手动输入并提示原因。
4. 创建任务弹窗的「目标分支」候选同步采用同一交集逻辑（与详情编辑一致）。
5. 无新后端接口；无架构组件变更。

## 方案（采用）

| 项 | 决策 |
|---|---|
| 交集算法 | 纯函数 `intersectBranchNameLists(lists)`：非空列表逐级求交，空列表集合视为无候选 |
| 数据源 | 任务详情：`repoBranchesCache`；创建任务：`projectBranchesMap` |
| UI | 有共有分支时用 `<select>`（含「手动输入…」）；否则 text + 提示 |
| 触发 | `startEdit` / `onProjectChange` / 创建任务选项目后批量 `fetch` |

## 非目标

- 不改 `merge_target_branch_name` 持久化字段语义
- 不新增聚合「共有分支」后端 API
- 不改工作分支模板逻辑
