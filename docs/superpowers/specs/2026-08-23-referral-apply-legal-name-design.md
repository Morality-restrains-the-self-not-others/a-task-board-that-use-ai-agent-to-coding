# 设计：申请推荐资格须填写个人名称

- **日期**: 2026-08-23
- **入口**: `/profile/referral/` 申请表
- **架构变更**: 无（既有申请 API 增字段；无新服务/事件）

## 根因

微信支付添加个人分账接收方、请求分账时，`name` 为选填；**一旦传入则与微信实名校验，不匹配即拒绝**。当前申请只收个人介绍，添加接收方省略 `name`，用户也不知道分账依赖实名。需求是申请时填写个人名称，并明确填错将导致后续分账失败。

## 方案

1. 申请表新增必填「个人名称」，并固定警示：须与微信实名完全一致，填错会导致分账失败、无法补分。
2. `POST .../referral-codes/apply/` 必填 `legal_name`（2–32 字，汉字/字母/·）。
3. 存入 `referral_code.legal_name`；审批登记接收方与发起分账时传给微信（SDK 加密）。
4. 存量无名称的记录仍省略 `name`（行为与现在一致）。

## 权限 / 路径 / 幂等

| 项 | 结论 |
|----|------|
| 权限 | 无新接口；已登录用户申请；超管列表只读展示名称 |
| 路径分片 | 既有用户中心页，L0 |
| 幂等 | 沿用申请 `Idempotency-Key`；登记接收方仍按 user_id |

## 领域

无新聚合。`ReferralApplication.legal_name` 为值对象。无新事件（仍是同一申请提交）。
