# 创建设计：创建任务结构化可选字段

**日期**: 2026-07-17  
**状态**: 已采用（goal-mode 自动选型，跳过用户确认）  
**范围**: 工作台 `/tenant/:tid/work-panel/` 创建任务弹窗

## 目标

在「创建任务」表单中增加以下**可选**输入字段，便于用户按 Agent 友好结构填写任务说明：

1. 任务背景
2. 当前问题是什么
3. 需要模型完成什么修改
4. 目标文件、模块或命令在哪里
5. 需要保持哪些原有行为不变
6. 是否禁止新增依赖
7. 建议验证方式

## 方案对比与决策

| 方案 | 说明 | 取舍 |
|------|------|------|
| A. 前端拼入 `description` | 提交前将非空结构化段落拼为 Markdown，仍走现有 `POST/PUT .../todos/` | **采用**：零后端/库表变更；auto_run 已消费 title+description |
| B. 独立 API/DB 字段 | 新列或 JSON metadata | 拒绝：改动面大，本期无查询/过滤结构化字段需求 |

**架构影响**: 无新服务、无新 HTTP 契约、无数据所有权变更 → **不更新** `docs/architecture/` ArchiMate 三件套。

## 交互设计

- 「任务描述」保留为自由补充说明（可空）。
- 其下增加可折叠区块「结构化任务说明（可选）」，默认在**创建**时展开；**编辑**时若能从既有 description 解析出段落则回填并展开，否则折叠且字段为空（完整正文仍在任务描述中）。
- 「是否禁止新增依赖」为三态选择：未指定 / 是 / 否。
- 其余字段为多行文本，均可空；全空时不改变 description 语义（仅提交自由描述）。
- 弹窗内容区可滚动，避免字段增多后按钮不可见。

## 组装与回解析

稳定标题（解析依赖）：

```markdown
## 任务背景
## 当前问题是什么
## 需要模型完成什么修改
## 目标文件、模块或命令在哪里
## 需要保持哪些原有行为不变
## 是否禁止新增依赖
## 建议验证方式
```

- 自由描述置于结构化段落之前（无额外标题，或解析时取首个 `##` 之前文本）。
- 「是否禁止新增依赖」正文写入 `是` / `否`。
- 编辑保存时：用当前表单字段重新 compose，覆盖 description，避免重复追加。

## 非目标

## 验收标准

1. 创建弹窗可见 7 个可选字段；均可留空提交。
2. 填写后创建，任务 description 含对应 Markdown 段落；auto_run 首指令可读到该内容。
3. 编辑已含段落的任务，字段可回填；保存不产生重复段落。
4. 相关单元测试通过；公网 SPA 经 `runall-lifecycle.sh build` 发布。
