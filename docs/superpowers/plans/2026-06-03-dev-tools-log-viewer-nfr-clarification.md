## NFR 概览表

| 类别 | 等级 | 一句话量化 |
|------|------|-----------|
| 性能 | L2 | 日志读取 P95 ≤ 300ms（2000 行场景） |
| 安全性 | L1 | 复用现有 localhost 访问控制 |
| 数据一致性 | L1 | 文件 append，OS 级原子写入 |
| 可观测性 | L2 | 日志行带时间戳，API 返回结构化 JSON |
| 可维护性 | L2 | 复用现有代码模式、CSS 变量、API 约定 |
| 容错机制 | L1 | 文件不存在返回空数组，不阻断操作 |
| 可伸缩性 | L0 | 跳过。单开发者工具，无扩展需求 |
| 可用性 | L0 | 跳过。无 SLA，runAll 进程生命周期内可用即可 |

## 逐增量 NFR 分析

### Increment 1: 后端 — DevToolLogRecorder + API

#### NFR 类别: 性能
- **等级**: L2 - 标准
- **量化目标**: `GET /api/dev/logs` 读取 2000 行 P95 ≤ 300ms（服务端处理时间）
- **说明**: 文件 seek + 倒序读取 2000 行应在 300ms 内完成。日志文件预期 ≤ 10MB，单文件操作。

#### NFR 类别: 安全性
- **等级**: L1 - 基础
- **量化目标**: 复用现有 `allowDevDatabaseReset` 的 localhost 守卫（仅 127.0.0.1 / localhost 可访问清除类操作）
- **说明**: 读取日志（GET）不设限；清空日志（POST）需 tool 参数校验白名单。

#### NFR 类别: 数据一致性
- **等级**: L1 - 基础
- **量化目标**: 文件写入使用 `O_APPEND`，OS 级别保证单行原子写入
- **说明**: 无分布式事务需求，单进程写入。

#### NFR 类别: 容错机制
- **等级**: L1 - 基础
- **量化目标**: 日志目录不存在时自动创建；日志文件不存在时 API 返回空数组（不报 500）
- **说明**: 不阻断主操作。写入失败仅 `log.Printf` 记录，不抛出异常。

### Increment 2: 前端 — 日志查看按钮 + 面板复用

#### NFR 类别: 可维护性
- **等级**: L2 - 标准
- **量化目标**: 新增 JS 代码遵循现有 `status.html` 命名约定，CSS 复用 `:root` 变量，API 响应格式与现有 `/api/logs` 一致
- **说明**: 零新依赖，零新 CSS 变量。

#### NFR 类别: 可观测性
- **等级**: L2 - 标准
- **量化目标**: 每条日志行带 `[YYYY-MM-DD HH:MM:SS]` 时间戳前缀；API 返回 JSON 结构 `{tool, lines: []}`
- **说明**: 日志面板 2s 自动刷新，便于实时追踪操作进度。

## 质量场景

### QS-01: 读取日志文件尾 2000 行
| 要素 | 内容 |
|------|------|
| 类别 | 性能 |
| 等级 | L2 |
| 刺激源 | 开发者点击「日志查看」按钮 |
| 刺激 | 请求读取 db-clear.log 最后 2000 行 |
| 制品 | GET /api/dev/logs?tool=db-clear&lines=2000 |
| 环境 | 正常（日志文件约 5MB） |
| 响应 | 返回 JSON `{tool: "db-clear", lines: [...]}` |
| 响应度量 | 服务端处理时间 P95 ≤ 300ms |

### QS-02: 开发工具操作过程中实时写日志
| 要素 | 内容 |
|------|------|
| 类别 | 数据一致性 |
| 等级 | L1 |
| 刺激源 | 开发者点击「清空全部数据库」 |
| 刺激 | 后端执行数据库中各步骤，每步 `Append` 一行 |
| 制品 | DevToolLogRecorder.Append() |
| 环境 | 正常 |
| 响应 | 每步完成后日志行立即持久化到文件 |
| 响应度量 | Append 调用后内容立即可被 Tail 读取（OS fsync 不强制，但 O_APPEND 保证可见性） |

### QS-03: 日志文件不存在时的优雅处理
| 要素 | 内容 |
|------|------|
| 类别 | 容错机制 |
| 等级 | L1 |
| 刺激源 | 开发者首次查看某工具日志 |
| 刺激 | 请求读取尚未创建的日志文件 |
| 制品 | GET /api/dev/logs?tool=conf-sync&lines=200 |
| 环境 | 正常 |
| 响应 | 返回 `{tool: "conf-sync", lines: []}` |
| 响应度量 | HTTP 200，前端显示「暂无日志」 |

### QS-04: 清空日志文件
| 要素 | 内容 |
|------|------|
| 类别 | 安全性 |
| 等级 | L1 |
| 刺激源 | 开发者点击「清空日志」按钮 |
| 刺激 | 前端 confirm 确认后发起清空请求 |
| 制品 | POST /api/dev/logs/clear `{tool: "db-clear"}` |
| 环境 | 正常 |
| 响应 | 文件截断为 0 字节，返回 `{status: "ok"}` |
| 响应度量 | HTTP 200，前端刷新后显示「暂无日志」 |

## 领域模型影响

| NFR 决策 | 模型影响 | 对应 DDD 动作 |
|----------|---------|-------------|
| 性能 L2（文件 tail 读） | DevToolLogRecorder 接口的 Tail 方法需保证 O(lines) 复杂度 | 仓储实现使用文件 seek + 倒序读，不加载全文件到内存 |
| 容错 L1（文件不存在不报错） | Tail/Clear 方法需区分「文件不存在」和「读取失败」 | 接口实现中对 `os.IsNotExist` 返回空结果而非 error |
| 可维护性 L2（复用现有模式） | 不引入新架构概念，在现有 domain/infrastructure 层追加 | DDD 步骤轻量化——仅新增一个 domain 接口 + 一个 infrastructure 实现 |

## 权衡与边界

### 取舍
- 选择文件级日志（简单可靠）而非数据库存储（过度设计），接受文件系统级性能
- 选择每工具独立文件（隔离清晰）而非合并文件（需要解析），接受稍多的文件句柄
- 不对日志文件做轮转（rotation）——由开发者手动清空，避免引入 logrotate 复杂度

### 明确不做什么
- 不实现日志搜索/过滤（V1 仅 Tail 查看）
- 不实现日志导出/下载
- 不实现日志级别（INFO/WARN/ERROR）分类
- 不做日志文件大小限制和自动轮转
- 不做 WebSocket 实时推送（2s 轮询足够）

### 升级触发条件
- 当日志文件超过 100MB 时 → 引入自动截断或轮转机制
- 当开发工具操作耗时超过 30s 时 → 引入 WebSocket 推送实时日志流
- 当需要跨机器查看日志时 → 将日志接入 Loki 集中式日志系统

## 跳过声明

- **可伸缩性**: 跳过。单开发者工具，无并发用户场景。文件系统可满足。
- **可用性**: 跳过。runAll 进程生命周期内可用即可，无独立 SLA 要求。
- **合规与隐私**: 跳过。处理的是运维操作日志，不含用户 PII。
