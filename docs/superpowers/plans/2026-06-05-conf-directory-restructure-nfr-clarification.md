## 跳过声明

本次变更为 **纯配置目录结构调整**（`conf/<服务>/` → `conf/<职能>/<服务>/`），属于以下跳过条件：

- ✅ **配置变更** — 仅重命名目录路径，不修改任何业务逻辑、数据流或外部依赖
- ✅ **不引入新数据流** — 所有端口、密钥、sync 协议内容不变
- ✅ **不引入新外部依赖** — 无新增服务或中间件

因此，所有 NFR 类别在当前变更中均 **不适用 (L0)**。具体理由：

| 类别 | 等级 | 跳过理由 |
|------|------|---------|
| 性能 | L0 | 目录重命名不影响运行时性能 |
| 可伸缩性 | L0 | 无架构变更 |
| 可用性 | L0 | 无运行时变更 |
| 安全性 | L0 | 无认证/授权/加密变更 |
| 数据一致性 | L0 | `git mv` 在 Git 层面保证原子性；无数据库变更 |
| 容错机制 | L0 | 不涉及网络调用或服务间通信 |
| 可观测性 | L0 | 日志/指标/追踪路径不变 |
| 合规与隐私 | L0 | 无数据处理逻辑变更 |
| 可维护性 | L0 | 变更本身即为可维护性改进；向后兼容通过 `git mv` 保留历史保证 |

## 唯一的隐性约束

虽然不触发 NFR 质量场景，但有一个工程约束需在实施计划中体现：

- **Sync 一致性**：迁移后 `conf-sync-all.sh` 必须 exit 0 且碎片内容与迁移前一致。此约束已纳入价值流 Increment 1 的验证方式。
