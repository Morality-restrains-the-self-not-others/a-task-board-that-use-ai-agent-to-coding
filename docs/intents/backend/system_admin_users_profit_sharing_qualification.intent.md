# 功能意图：超管用户列表展示是否获得分账资格

## 意图

系统管理员在 `/system-admin/users/` 用户表格中看到每名用户**当前**是否具备微信分账/推荐分成资格，无需点进申请 tab。

## 角色

- 系统管理员（superuser / 既有 system-admin 路由）

## 行为

1. `GET /api/system-admin/users/` 每条用户增加 `has_profit_sharing_qualification`：`true` / `false` / `null`。
2. `true`：taskReferral `referral_code` 为 approved 且未过期（与支付时刻现查口径一致）。
3. `false`：无活跃资格（未申请、拒绝、取消、过期）。
4. `null`：资格服务不可达；列表仍 200。
5. 资格数据由 taskAuth 对当前页 user id 调用内部批量接口获得；禁止直连 referral 库。

## 非目标

- 不在本列表审批/取消资格。
- 不改变支付打标逻辑。
- 不对浏览器暴露内部批量接口。

## 业务意图 → 事件对照

| 业务意图 | 事件名（过去式） | 发布点 | 消费者 | MQ类型/契约 |
|----------|------------------|--------|--------|-------------|
| 超管查看用户分账资格列 | 无对应事件 | — | — | 书面例外：只读投影，不改变资格状态 |

## 验收标准

- 有活跃资格的用户单元格为「是」。
- 无资格为「否」；下游失败为「—」。
- 列在「角色」与「操作」之间。
- 非超管无法读取该字段（沿用列表 403）。
