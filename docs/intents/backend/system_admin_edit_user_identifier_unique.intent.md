# 功能意图：系统管理编辑用户时拒绝已被占用的手机号/邮箱

- **日期**: 2026-08-28
- **状态**: 已实施
- **接口**: `PUT|PATCH /api/system-admin/users/{id}/`
- **页面**: `/system-admin/users/` 编辑用户模态框「手机号」

## 背景与目标

运营在系统管理编辑用户时把手机号改成已被其他用户使用的号码。原先 `patchUserAsAdmin` 只写布尔标志、忽略 `phone`/`email`，接口仍 200，表单关闭且无提示，号码实际未变。

## 范围与边界

- 范围内：admin PUT/PATCH 对 `phone`、`email` 做占用校验；占用则 409 且不改绑定；空闲则写入 login method。创建用户同样预检手机号。前端编辑/添加弹窗内联展示错误（`data-traceId`）。用户名/密码由同路径后续提交落地。空 `phone` 键作废绑定见 `system_admin_unbind_user_phone`。
- 范围外：管理员强制收回（reclaim）、短信验证码。

## 约束与风险

- 不得把完整手机号/邮箱写入日志（PII）。
- 409 不得提供 reclaim（那是持有 SIM 的自助换绑，不是运营抢号）。
- 占用校验失败时不得部分写入另一标识。

## 验收标准

1. 目标用户改到其他活跃用户已绑定的手机号 → 409，`code=phone_taken`，中文 detail 含「手机号」，原绑定不变。
2. 空闲手机号 → 200，login method 更新。
3. 邮箱被占用 → 409，`code=email_taken`。
4. 编辑弹窗保持打开，手机号字段下展示错误文案，错误节点带 `data-traceId`。
