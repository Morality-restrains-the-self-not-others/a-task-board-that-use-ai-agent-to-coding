# 意图：超管「支付与签署」抽屉中未挂到支付的协议签署

- 日期：2026-08-25
- 状态：accepted
- 架构：v63

## 背景与目标

超管在用户管理打开「支付与签署」时，会看到协议签署记录。支付流水与协议签署不是 1:1 外键：后端只把最新「支付服务条款」挂到用户支付行。注册时的服务协议、历史版本支付条款因此无法挂到某一笔支付上。旧文案「未绑定流水的签署」是内部行话，运营会误以为签署缺失或数据损坏。

## 范围与边界

- 范围内：抽屉区块标题、说明、每条签署的协议种类标签（服务协议 / 支付服务条款）
- 范围外：把签署 1:1 绑定到 `billing_resource_order.consent_id`（见 OPT-20260825-017）

## 业务意图 → 事件对照

**无对应事件**：只读超管抽屉文案，无服务端业务状态变更。

| 业务意图 | 事件 | 发布点 | 消费者 | MQ类型/契约 |
|----------|------|--------|--------|-------------|
| 展示未挂到支付的协议签署 | — | — | — | 无对应事件：只读文案 |

## 验收标准

1. 标题为「其他协议签署」，不得出现「未绑定流水的签署」
2. 说明文字写明这不表示签署缺失
3. 每条展示协议种类 + 版本 + 签署时间
4. 已挂在支付行上的 consent 不重复出现在该区块
