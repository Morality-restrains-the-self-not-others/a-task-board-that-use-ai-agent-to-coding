# 功能意图：管理端赠送须显式填写数量

## 意图

系统管理员在「赠送资源」页只改 VIP 时，不得因表单预填数量而误赠任务帖并生成零元赠送订单。数量必须由操作者显式填写。

## 角色

- 系统管理员 / 平台员工（既有赠送页权限，无新端点）

## 行为

1. 资源行数量默认留空（placeholder 提示须填写）。
2. 未填有效数量（≥1）的行不进入 POST `resources`。
3. 只选 VIP、未填数量：POST `resources: []` + `membership_tier`，后端不建赠送订单。
4. 提交前展示核对文案：是否赠送资源、是否生成赠送订单、是否改 VIP。
5. 提交走 `createClickGuard`，同一意图 POST 带同一 `Idempotency-Key` 与 body `idempotency_key`。

## 非目标

- 不撤销历史误赠订单（`ORD-20260822-877397588196749312-879129787220656128` 仍保留，剩余 100 未消耗）。
- 不改赠送 API 鉴权与资源类型。

## 业务意图 → 事件对照

| 业务意图 | 事件名（过去式） | MQ类型/契约 | 发布点 | 消费者/副作用 | 例外理由 |
|----------|----------------|------------|--------|--------------|---------|
| 管理员显式赠送或仅调 VIP | — | — | 既有 `POST .../admin_grant_points/` | 配额/会员 | 纯前端校验与默认值修正；服务端写路径与既有赠送意图相同，不新增 MQ |

## 验收

- 打开赠送页，数量输入为空，不是 100。
- 选租户 + 仅选 VIP1 → 预览含「不会生成赠送订单」；POST `resources` 为空数组。
- 填数量 100 再提交才出现任务帖赠送订单。
- 连点提交只发出一次 POST。
