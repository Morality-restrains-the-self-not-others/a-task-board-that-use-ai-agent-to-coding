# 功能意图：新用户 onboarding 默认公司名为「${user}的公司」

## 背景与目标

新用户注册后进入公司引导页时，输入框默认应是「{用户展示名}的公司」，而不是空值、纯用户名，或中性占位「我的公司」。用户仍可改名后确认。

`${user}` = 用户展示名：优先个人昵称 / 注册用户名（邮箱本地部分）；都空时回退「我的公司」。

## 范围与边界

- 范围内：
  - `taskFE` Onboarding 输入框预填
  - `taskEvents` `USER_CREATED` → 自动建公司时的默认公司名
- 范围外：
  - 存量已确认过的自定义公司名不回写
  - 不把公司名写入 `member_name`（仍用个人昵称）
  - 不使用手机号作为 `${user}`

## 约束与风险

- 空展示名不得生成「的公司」或雪花 userID。
- 展示名已以「的公司」结尾时不得重复拼接。
- 人员管理页不得把默认公司名当成成员昵称（既有误种子检测保留「我的公司」及 `member_name == company.name`）。

## 验收标准

1. 无已有公司时，引导页输入框预填 `{展示名}的公司`；展示名为空则预填「我的公司」。
2. 已有公司且名称是自动生成形态（空 / 「我的公司」 / 等于展示名）时，输入框改为 `{展示名}的公司`，用户确认后写入。
3. 已有自定义公司名时保持原名。
4. `USER_CREATED` 自动建公司使用同一公式；空 username 且有个人昵称时用「{昵称}的公司」。
5. 创建者 `member_name` 仍是个人昵称，不是公司名。

## 业务意图 → 事件对照

| 业务意图 | 事件名（过去式） | MQ类型/契约 | 发布点 | 消费者/副作用 | 例外理由 |
|---------|----------------|-----------|--------|--------------|---------|
| 新用户注册 | USER_CREATED | Kafka `user-created`（存量） | taskAuth register / wechat / phone | `0_create_company` 建公司 | 本期不改事件契约，只改默认公司名 |
| 自动/引导创建公司 | COMPANY_CREATED | Kafka `company-created`（存量） | taskEvents usercreated handler | 下游租户初始化 | 存量路径 |

## 实施计划

1. 共享纯函数：`PersonalCompanyName(display) → "{display}的公司"`（空 / 「我的公司」不拼接）。
2. `CreateCompanyForUser`：username → 个人昵称 → 公式。
3. Onboarding：拉 profile 展示名并预填；自动生成名可被公式覆盖。
4. 单测锁定公式与引导页预填。
5. 微信建号先写 `auth_user_profile`，再发 `USER_CREATED`，建公司经 batch/details 可读昵称。
