# 基准分支候选：按时间排序且下拉固定在输入框下方

## 业务意图 → 事件对照

**无对应事件**：纯前端展示/交互 + 只读分支列表排序，无服务端业务状态变更意图。

| 业务意图 | 事件名（过去式） | 发布点 | 消费者/副作用 | 例外理由 |
|---------|----------------|--------|--------------|---------|
| 基准分支下拉排序与定位 | — | — | — | 纯前端交互；分支列表 API 仅调整返回顺序 |

## 变更记录

- 2026-08-11：创建任务/任务详情基准分支候选改为自定义下拉；后端分支列表按最近更新时间降序；下拉始终渲染于输入框下方。
- 2026-08-11：Teleport 下拉 z-index 须高于 `.app-modal-overlay`（9999）及其子面板（10000），否则请求成功但列表被遮罩挡住不可见；改为 inline `zIndex: 11000`。

## 背景与目标

工作面板创建任务弹窗中「基准分支」使用原生 `datalist`：浏览器可能把建议列表翻到输入框上方，且候选顺序不受控。目标：

1. 候选按分支最近更新时间降序（新→旧）。
2. 下拉菜单始终出现在输入框正下方（不翻到上方）。

## 范围与边界

- 范围内：创建任务弹窗基准分支；任务详情编辑态「手动输入」基准分支；`GET .../branches/` 返回顺序。
- 同弹窗工作分支/目标分支：一并改用可定位的自定义建议下拉（定位问题同类）。
- 范围外：不改变自由输入 commit hash / 手写分支名能力；不改变提交任务的后端契约字段。

## 约束与风险

- 原生 `datalist` 无法控制浮层位置 → 必须自定义下拉。
- GitHub 分支列表 API 不带 commit 时间：有时间戳的提供方按时间排；无时间戳时保持稳定相对顺序（不擅自字母排序打乱既有习惯）。
- 下拉交互遵循「单击展开、双击收起」。

## 验收标准

1. 打开创建任务 → 焦点基准分支：建议列表在输入框下方且可见（压在 modal 遮罩之上）。
2. 列表顺序与后端按更新时间降序一致（有时间戳时新分支在上）。
3. 可从列表点选，也可手输不在列表中的值（含 commit hash）。
4. 任务详情编辑态手动输入基准分支行为一致。
5. 分支 API 返回后，若输入框仍聚焦/已打开，下拉应随 options 出现。
