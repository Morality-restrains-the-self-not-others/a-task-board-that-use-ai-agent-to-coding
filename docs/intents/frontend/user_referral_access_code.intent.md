# 功能意图：无推荐资格也展示 accessCode

- **日期**: 2026-08-19
- **状态**: 已实施
- **页面**: `/profile/referral/`

## 背景与目标

推荐页在用户「暂无推荐资格」时仍展示分享链接。此前链接依赖 JS 可读的 `userId` cookie；生产环境该 cookie 为 HttpOnly，导致 `?accessCode=` 为空。资格只应控制分成，不应阻止发码。分享码必须是服务端持久化的不透明码，**禁止**用 `userId` 或 `u{userId}` 派生。申请推荐资格因分成名额有限，须填写个人介绍供审批。

## 验收标准

1. 已登录且 `has_active_code=false` 时，推荐码与推荐链接的 `accessCode` 为状态接口返回的不透明码，不得为空，且不得等于 `userId` / `u{userId}`。
2. 状态接口 `GET /api/accounts/users/referral-codes/status/` 始终返回 `access_code`；前端**只**使用该字段展示分享码。
3. 接口未带 `access_code` 时，前端不得回退拼接 `u{userId}`；链接省略 `accessCode` 查询参数。
4. 「暂无推荐资格」提示仍展示；分成比例文案来自 `referral_rate_display`（后端固定 5%），不得把微信上限 30% 当佣金。
5. 未获/过期/可再申请时须填写个人介绍（20–500 字）才能提交；页面说明分成名额有限。
6. 申请区须说明系统将绑定账号标识与用户身份信息并提交微信支付做一致性校验；未勾选同意则申请按钮不可用；提交体含 `identity_bind_consent: true`。
7. `/auth/register/?accessCode=` 须把该码随注册请求 `access_code` 提交；**仅新建账号**注册成功后服务端绑 `billing_referral_edge`（不要求推荐资格）。已有手机号返回 400「该手机号已被注册，请直接登录」，不绑边。
8. 可为不同渠道创建独立码与链接；可按渠道与时间段查看推荐人数与分账。是否分账以被推荐用户**下单时**推荐人是否具备资格为准：推荐时无资格、之后获资，仍可从已推荐用户的后续下单获得分成。
9. 已获推荐资格时，页面根据 `wechat_receiver_status` 提示是否已在微信分账后台登记；`pending_openid` 须先微信登录，`failed` 刷新可重试。本地资格不等于商户平台接收方。

## 业务意图 → 事件对照

| 业务意图 | 事件 | 例外理由 |
|----------|------|----------|
| 展示分享码 | — | 纯查询/展示，无跨服务最终一致需求 |
| 提交申请（含介绍） | REFERRAL_APPLICATION_SUBMITTED | 由 taskReferral 记结构化日志；见 backend intent |
