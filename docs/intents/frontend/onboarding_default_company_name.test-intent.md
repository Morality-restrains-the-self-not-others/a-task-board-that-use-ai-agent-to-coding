# 测试意图：新用户 onboarding 默认公司名为「${user}的公司」

## 对应功能意图

`docs/intents/frontend/onboarding_default_company_name.intent.md`

## 测试目标

锁定默认公司名公式，以及 Onboarding 预填 / `USER_CREATED` 建公司使用同一公式。

## 测试分层

| 层 | 覆盖 |
|----|------|
| 单元（Go） | `PersonalCompanyName` / `ResolvePersonalCompanyName`；`CreateCompanyForUser`；`USER_CREATED` handler |
| 单元（Vitest） | `defaultOnboardingCompanyName` / `isAutoGeneratedCompanyName`；Onboarding 预填 |
| 回归 | 空 username 仍不为 userID；member_name 仍为个人昵称 |

## 用例矩阵

| # | 场景 | 类型 | 期望 |
|---|------|------|------|
| T1 | display=`张三` | Go/JS 纯函数 | `张三的公司` |
| T2 | display 为空 | 同上 | `我的公司` |
| T3 | display=`我的公司` | 同上 | `我的公司`（不拼成「我的公司的公司」） |
| T4 | display 已以「的公司」结尾 | 同上 | 原样返回 |
| T5 | USER_CREATED username=`evtuser` | Go handler | 公司名 `evtuser的公司` |
| T6 | username 空且无昵称 | Go | 公司名 `我的公司`，不是 userID |
| T7 | username 空且昵称=`软刀` | Go | 公司名 `软刀的公司`；member_name=`软刀` |
| T8 | Onboarding 无已有公司、profile 昵称=`软刀` | Vitest | 输入框=`软刀的公司` |
| T9 | 已有公司名=`我的公司`、昵称=`软刀` | Vitest | 输入框改为 `软刀的公司` |
| T10 | 已有自定义公司名 | Vitest | 保持原名 |
| T11 | 微信建号后发 USER_CREATED 时 | Go | `POST /api/internal/users/batch/details/` 已返回微信昵称；事件 username 仍为空 |

## 数据与环境

- Go：`saastest.IntentMux`（含 `ProfileNicknames`）
- 前端：Vitest + Vue Test Utils，mock `apiFetch`
