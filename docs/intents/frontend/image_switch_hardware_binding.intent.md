# 意图：切换容器镜像后硬件规格必须与镜像架构重新对齐

## 背景与目标

项目默认镜像与硬件运行模版、任务评论所选镜像与硬件面板选中实例，目前是两条独立绑定。用户切换镜像（尤其跨 x86_64 / arm64）后，旧实例规格仍会用于自动运行或 start-vm，直到云侧报架构不匹配。

目标：切换项目默认镜像时，若新镜像与当前运行模版实例架构不匹配，**必须同一次 PATCH 提交完整且匹配的 `server_run_template`，否则 400 且不落库**。任务侧换 `@镜像` 在启动路径硬拦。

设计文档：`docs/superpowers/specs/2026-08-21-image-switch-hardware-binding-design.md`（审批：硬拦截）。相关前序：`task_detail/026_hardware_config_in_image_card`、`027_image_select_in_comment_composer`。

## 范围与边界

- 范围内：项目详情默认镜像 + `ProjectRunTemplatePanel`；任务详情 `@镜像` + 硬件面板；`resolvePrimaryImageArchitecture`；`loadRegions` 代际；`taskProjectService` PATCH 硬拦截（先校验再写）；`inferInstanceArchitecture` 收紧。
- 范围外：厂商门户云主机镜像表单；自动改选另一架构的近似实例；静默剥离实例后仍 200；新 API / 新 Kafka 事件；架构视图 vN。

## 约束与风险

- 不把镜像与硬件合成单一 PATCH 必填包。
- 剥离实例后允许镜像先落库会留下不一致窗口；已否决。
- 镜像 lookup 失败时拒绝保存，避免漏检。

## 验收标准

1. 有 `selectedImageId` 且已安装目录能命中时，实例过滤架构以目录 `target_architectures` 为准，不被陈旧 `task.container_image` 盖住。
2. 项目页跨架构更换默认镜像：仅 PATCH 镜像 → 400 且库不变；同单提交完整匹配模版 → 200。同架构可只 PATCH 镜像。
3. 任务页更换 `@镜像` 后：临时配置不兼容实例被清空；项目模版不匹配则禁止启动。
4. 快速连换镜像不会把上一张镜像的地域列表应用到新镜像。
5. `ecs.r6.xlarge` 推断为 x86_64；`ecs.r6r.xlarge` 为 arm64。
6. start-vm 架构不匹配错误仍返回给前端。
