# 意图：任务详情 Fork 确认是否自动运行

## 业务意图 → 事件对照

用户确认后仍走既有 `POST .../todos/`（含 `fork_from` / `auto_run`）。每份副本触发既有 `TASK_CREATED`；不新增事件类型。

| 业务意图 | 事件名（过去式） | 发布点 | 消费者/副作用 | 例外理由 |
|---------|----------------|--------|--------------|---------|
| Fork 仅派生 1 份 | `TASK_CREATED` | `createTaskOnce` | 看板 SSE、配额 | 不新增事件类型 |
| Fork 自动运行按模型复制 | `TASK_CREATED` × N | `createTaskOnce`（每份不同 `agent_models`） | 看板 SSE、配额、auto_run 启服与模型覆盖 | 差异在运行模型，不新增事件名 |

## 业务意图

租户用户在任务详情页点击 Fork 时，须先确认派生方式：

- **不自动运行，仅派生**：始终制作 1 个同构副本。智能体资源/模型选择不影响结果。
- **自动运行并派生**：先选智能体资源（公司默认 / 工作空间默认 / 个人配置），再选一个或多个智能体（该配置中可切换的模型名称）；选几个就复制几份，每份用该模型自动运行。

避免误触发 auto_run 启动云资源。

## 成功路径

1. 用户打开任务详情 → 点击 Fork。
2. 弹出确认模态；用户选择派生方式。
3. 「取消」→ 不创建。
4. **仅派生**：无数量框，始终 1 份。`auto_run=false`。打开该任务。
5. **自动运行**：Git 身份 / OAuth 门禁（有仓时）；选智能体资源后多选模型。按模型循环 POST（`auto_run=true`，每份 `agent_models: [{provider, model}]`），`Idempotency-Key=${batch}:${i}`。服务端把模型写入 auto_run pending agent，首 job 覆盖 `TASK_AGENT_MODEL`。N>1 只打开第一份。
6. 有关联仓库时，自动运行须选当前用户 Git 身份；仅派生不要求。
7. 新任务进度落在工作区第一列。

## 权限

与「创建工作区任务」一致。模型名必须属于所选智能体资源配置的支持模型列表。
