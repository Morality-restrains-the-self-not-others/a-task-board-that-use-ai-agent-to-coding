# 意图：任务详情硬件卡仅作启动配置，不关联运行态

## 背景与目标

「环境与硬件」卡（意图 026）挂在评论区镜像下。**该卡是 `@镜像` 启动所用硬件配置的 UI 真源**：选镜像 → 在本卡定规格 → 提交带 `@镜像` 的评论即按此规格启机。卡内不展示、不绑定任何运行中状态；运行态由各评论执行细节关联。

## 范围与边界

- **范围内**：从任务详情硬件面板移除全部生命周期控件与运行态文案；UI 不读运行态
- **范围内**：临时配置模式下评论 `@镜像` 携带 `server_run_template`，替代项目模版
- **范围内保留**：实例/网络/自动释放/临时配置
- **范围外**：新 Kafka 事件名、评论表 DDL、项目运行模版页、把启动按钮迁到运行状态 Tab

## 约束与风险

- 临时配置不完整时不得把残缺模版写入事件；composer 提示无法用该临时规格启动，**不拦截发评**
- Playwright 不得再依赖 `#start-server-btn`

## 行为约定

1. 未 `@镜像`：不渲染镜像下拉、不渲染硬件卡
2. 出现 `@镜像`：自动展开硬件卡；镜像以 mention 为准，不再常驻独立下拉
3. `#hardware-config-section` 内永不出现启停跳转与 `start-server-disabled-reason`
4. 硬件卡不因服务器已运行而禁用表单
5. 停止 / 跳转 / 启动进度只在各评论执行细节
6. 临时配置完整时 `@镜像` 用卡内规格；不齐则不写 override、仍可发评，启动回落项目模版（若有）

## 业务意图 → 事件对照

|---------|----------------|--------|--------------|---------|
| 硬件卡与运行态解耦 | — | — | — | 纯前端显隐 |
| 评论 @镜像 按当前启动配置开机 | TASK_COMMENT_IMAGE_MENTIONED | taskTaskService | `1_start_vm_for_at_mention` | 可选 `server_run_template` 覆盖项目模版 |

## 验收标准

- 任意运行态下，硬件卡无启停跳转按钮与「已在运行」提示
- 各评论执行细节仍能展示并操作该评论关联的运行态
- 项目模版页硬件面板行为不变
