# 意图：任务详情将服务器硬件配置并入环境与硬件卡（挂在评论区镜像下）

## 摘要
任务详情页「服务器硬件配置」不再作为服务器信息区独立 Tab，而是嵌套在「环境与硬件」卡片内；该卡由评论 composer 在 `@镜像` 后**直接渲染**（不经 Teleport），表示所选镜像的运行硬件环境。镜像选择见 `027_image_select_in_comment_composer`。

## 用户价值
- 「镜像 → 环境与硬件」自上而下形成「选什么跑、用什么环境跑」的连贯心智
- 避免环境与硬件卡游离在页面上方、与镜像选择脱节造成误解
- 硬件选型依赖当前选中镜像的 CPU 架构，与环境参数同卡更符合工作流

## 行为约定
1. 评论区 `@镜像` 后渲染 `CommentComposerHardwareCard`（`data-testid="comment-composer-env-hardware-slot"`），内含「环境与硬件」卡与 `ServerConfigHardwarePanel`；**不经 Teleport**
2. 「环境与硬件」卡内仅为**启动时硬件配置**（不关联运行态）；挂在智能体资源配置行**下方**（见 `028`）；卡内不另挂与面板重叠的 `hardware-config-comment-bar`；启停/运行态在各评论执行细节（见 `029`）
3. 服务器信息 Tab 不再包含「服务器硬件配置」；Runtime 区顶部不再常驻该卡
4. 默认服务器信息 Tab 为「服务器运行状态」（非 hardware）
5. 评论区「临时配置」滚动定位该卡内硬件面板，不切换 Tab
6. 项目运行硬件模版页（`ProjectRunTemplatePanel`）仍独立使用硬件面板（非 embedded）
7. 临时硬件配不齐：composer 提示无法用该临时规格启动，**不拦截发送评论**；不完整 `server_run_template` 不写入 POST（有项目模版则启动回落项目模版）

## 非目标
- 不改变启动 API / 模版持久化契约
- 不把硬件面板再 Teleport 回 ServerConfig.logic
