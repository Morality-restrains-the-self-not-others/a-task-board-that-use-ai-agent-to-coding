# 意图：Chrome 插件工作空间下拉去重并按租户区分同名项

## 背景与目标

- 背景：用户 OAuth 登录后，悬浮面板工作空间下拉出现两个同名选项。根因不是 DOM 渲染两次，而是 `getWorkspaces()` 按 `/me` 的 `companies` 逐租户拉列表后拼成一条下拉。公司创建时默认工作空间名称固定为「用户的工作空间」（`taskEvents` `createDefaultWorkspaceDirect`）。用户同时属于个人租户与其它公司时，两条记录 id 不同、名称相同；若 `/me` 还返回重复 `company_id`，同一 id 还会被追加两次。Web 工作面板先选租户再列工作空间，不会把跨租户同名项叠在同一下拉里。
- 目标：浮窗与 DevTools 面板的工作空间下拉按工作空间 id 只出现一次；跨租户同名时用「名称 · 公司名」区分，避免用户选错。

## 范围与边界

- 范围内：`taskChromePlugin` 聚合工作空间列表（`getWorkspaces()` 无 companyId）、下拉 option 文案；公司列表去重（含 `resolveDaydaymoneyMeta` 同类遍历）。
- 范围外：不改后端默认工作空间命名；不改 Web 工作面板；不合并不同 id 的真实工作空间。

## 约束与风险

- option `value` 仍是工作空间 id，提交任务路径不变。
- 仅一间公司且名称不冲突时，文案保持原 `name`，避免无谓加长。

## 验收标准

1. `/me` 返回两个相同 `company_id` 时，对该租户工作空间列表只请求一次，结果按 id 去重。
2. 两个租户各有一个名为「用户的工作空间」的工作空间时，下拉两项 id 不同，文案分别为 `用户的工作空间 · <公司A>` 与 `用户的工作空间 · <公司B>`。
3. 停用成员（`is_active === false`）对应公司不进入聚合。
4. `taskChromePlugin` 下相关单测通过。

## 实施计划

1. 纯函数 `lib/workspace-list.js`：公司去重、工作空间 id 去重、option 文案。
2. `getWorkspaces()` / `resolveDaydaymoneyMeta` 使用公司去重；浮窗与面板渲染使用文案函数。
3. 单测覆盖去重与同名消歧。
