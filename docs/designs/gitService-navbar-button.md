# 设计文档：导航栏增加 GitService 跳转按钮

**日期**: 2026-06-24  
**状态**: 待审批  
**影响范围**: `conf/infra/git-service/config.yaml` → `conf/frontend/vue/sync.manifest.yaml` → `conf_loader.py` → `vite.config.js` → `Navbar.ui.vue`

---

## 1. 需求概述

在项目列表页面的导航栏中，增加一个跳转到 gitService（自托管 GitLab CE）的按钮。按钮的目标 URL 遵循配置链路：

```
conf/infra/git-service/config.yaml        ← 配置源（基础设施层）
       │  sync.manifest.yaml 同步
       ▼
conf/frontend/vue/git-service.yaml        ← 前端配置空间（生成文件）
       │  load_app_config("frontend/vue") 合并
       ▼
build_runtime_snapshot() → out["vue"]     ← 运行时快照
       │  vite.config.js 读取 v.publicUrl
       ▼
import.meta.env.VITE_GIT_SERVICE_PUBLIC_URL  ← 前端环境变量
       │
       ▼
Navbar.ui.vue  "代码仓库" 按钮
```

---

## 2. 现状分析

### 2.1 当前导航栏 (`Navbar.ui.vue`)

```
┌──────────────────────────────────────────────────────────────────┐
│  AI项目推进平台    价格              [系统管理|工作面板] [头像] [退出] │
└──────────────────────────────────────────────────────────────────┘
```

- 左侧: Logo + "价格" router-link
- 右侧: 平台角色→「系统管理」（有公司时并列工作面板/公司下拉）/ 普通用户→工作面板或公司下拉 + 头像昵称 + 退出
- 无 gitService 入口

### 2.2 现有 gitService 配置

`conf/infra/git-service/config.yaml`:
```yaml
allowedHost: http://gitlab.daydaymoney.com
host: 127.0.0.1
port: 8012
sshPort: 2222
```

该配置通过 `conf_loader.py` 的 `JSON_KEY_TO_APP_DIR` 映射（`"gitService"` → `"infra/git-service"`）加载到运行时快照 `out["gitService"]`。但**前端 `vite.config.js` 未读取此块**。

### 2.3 sync.manifest.yaml 机制

`conf/frontend/vue/sync.manifest.yaml` 当前内容：

```yaml
version: "1"
fragments:
  - from: ../../core/django/config.yaml
    to: django.yaml
    pick: [host, port, allowedHost, internalApiBase]
```

`runAll/scripts/conf-sync.py` 读取 manifest → 从源文件 pick 指定字段 → 生成带 `# GENERATED` 头部的 fragment YAML。

当前 `conf/frontend/vue/` 目录已有生成文件 `django.yaml`（由 sync 产出），但 `load_app_config("frontend/vue")` **不会自动合并它**——仅合并 `config.yaml` + `config.local.yaml` + `docker-infra.yaml`。

### 2.4 配置加载链路

```
load_app_config("frontend/vue")
  → 读 config.yaml
  → merge config.local.yaml（如果有）
  → merge docker-infra.yaml（如果有）
  → 返回 (不含 django.yaml, task-auth.yaml 等 sync 生成的 fragment)

vite.config.js → conf-read.py snapshot-json → build_runtime_snapshot()
  → main.vue = load_app_config("frontend/vue")
  → main.gitService = load_app_config("infra/git-service")  ← 已存在但未使用
```

## 3. 设计方案

### 3.1 配置源：`conf/infra/git-service/config.yaml`

新增 `publicUrl` 字段（用户可访问的 GitLab Web UI 公开地址）：

```yaml
allowedHost: http://gitlab.daydaymoney.com
host: 127.0.0.1
port: 8012
sshPort: 2222
publicUrl: http://gitlab.daydaymoney.com       # ← 新增
```

| 字段 | 语义 | 受众 |
|------|------|------|
| `allowedHost` | GitLab 容器自身绑定的域名 | GitLab 进程 |
| `host:port` | GitLab 容器监听地址（本机回环） | runAll 编排 |
| `sshPort` | GitLab SSH 端口 | Git 客户端 |
| **`publicUrl`** | **用户浏览器访问 GitLab Web UI 的入口 URL** | **前端导航 / 邮件链接** |

### 3.2 同步片段：`conf/frontend/vue/sync.manifest.yaml`

新增 fragment，将 gitService 的 `publicUrl` 同步到前端配置空间：

```yaml
version: "1"
fragments:
  - from: ../../core/django/config.yaml
    to: django.yaml
    pick: [host, port, allowedHost, internalApiBase]
  - from: ../../infra/git-service/config.yaml      # ← 新增
    to: git-service.yaml                            # ← 新增
    pick: [publicUrl]                               # ← 新增
```

执行同步后生成 `conf/frontend/vue/git-service.yaml`:

```yaml
# GENERATED by conf/vue/sync.sh — DO NOT EDIT
# source: conf/infra/git-service/config.yaml
# synced_at: 2026-06-24T...
publicUrl: http://gitlab.daydaymoney.com
```

### 3.3 配置加载：`conf_loader.py`

`load_app_config()` 在合并 `docker-infra.yaml` 之后，追加合并 `git-service.yaml`：

```python
# task2app/Saas_project/config/conf_loader.py

def load_app_config(app_dir, *, include_test=False):
    # ... 现有逻辑 ...
    frag = app_path / "docker-infra.yaml"
    if frag.is_file():
        cfg = _deep_merge(cfg, _load_yaml(frag))
    # 新增：合并 git-service 同步片段
    frag = app_path / "git-service.yaml"            # ← 新增
    if frag.is_file():                               # ← 新增
        cfg = _deep_merge(cfg, _load_yaml(frag))     # ← 新增
    # ...
```

合并后，`out["vue"]` 中将包含 `publicUrl` 字段。

> **技术债务说明**：当前 `docker-infra.yaml` 采用硬编码文件名加载。若未来 sync 生成的 fragment 增多，可重构为通配加载 `app_path.glob("*.yaml")`，排除 `config.yaml`、`config.local.yaml`、`config.test.yaml`、`sync.manifest.yaml`。本次遵循现有模式。

### 3.4 构建注入：`vite.config.js`

在 `loadMergedPortConfig()` 中，从 `main.vue` 提取 gitService 公开 URL：

```javascript
// vite.config.js — loadMergedPortConfig() 内

// 从 vue 配置中提取 gitService 公开 URL（经 sync.manifest 同步）
const v = main.vue || {}
const gitServicePublicUrl =
  typeof v.publicUrl === 'string' && v.publicUrl.trim()
    ? v.publicUrl.trim().replace(/\/+$/, '')
    : ''
```

在返回值中暴露：

```javascript
return {
  // ... 现有字段 ...
  gitService: {
    publicUrl: gitServicePublicUrl,
  },
}
```

通过 `define` 注入（与其他环境变量放在一起）：

```javascript
define: {
  // ... 现有 ...
  'import.meta.env.VITE_GIT_SERVICE_PUBLIC_URL': JSON.stringify(gitServicePublicUrl),
}
```

> **为什么从 `main.vue.publicUrl` 而非 `main.gitService.publicUrl` 读取？**  
> 遵循用户指定的 sync.manifest 链路：配置从 `conf/infra/git-service/` → sync → `conf/frontend/vue/` → `load_app_config` 合并 → `out["vue"]`。  
> `main.gitService.publicUrl` 作为回退方案也可用（`build_runtime_snapshot` 已加载 gitService 块），但我们以 sync 链路为准。

### 3.5 UI 层：`Navbar.ui.vue`

在 `<script setup>` 中声明 URL 常量：

```javascript
const gitServiceUrl = import.meta.env.VITE_GIT_SERVICE_PUBLIC_URL || ''
```

在模板中，左侧 "价格" 右侧新增按钮：

```html
<!-- 新增：gitService 代码仓库跳转（仅已登录且配置了 URL 时显示） -->
<a
  v-if="isUserAuthenticated && gitServiceUrl"
  :href="gitServiceUrl"
  target="_blank"
  rel="noopener noreferrer"
  class="nav-link hover:text-primary transition-colors"
  data-testid="nav-git-service"
>
  代码仓库
</a>
```

#### 设计决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 放置位置 | 左侧 "价格" 右侧 | 与现有导航项聚集 |
| 显示条件 | `isUserAuthenticated && gitServiceUrl` | 需要登录态；未配置不显示 |
| 打开方式 | `target="_blank"` | gitService 是外部系统 |
| 安全属性 | `rel="noopener noreferrer"` | 防止 `window.opener` 攻击 |
| 标签文案 | "代码仓库" | 与 Sidebar "项目列表""镜像市场" 风格一致 |

```bash
python3 runAll/scripts/conf-sync.py vue
cat conf/frontend/vue/git-service.yaml
# 预期: publicUrl: http://gitlab.daydaymoney.com
```

### 7.2 前端组件测试

| 场景 | 预期 |
|------|------|
| URL 已配置 + 已登录 | 按钮可见，`href` 正确 |

2. 登录 → 访问 `/tenant/{id}/projects`
3. 确认导航栏出现 "代码仓库" → 点击 → 新标签页打开 GitLab
4. 未登录 → 确认按钮不显示
