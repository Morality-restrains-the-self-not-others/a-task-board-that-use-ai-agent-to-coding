# 云端 Coding：从线上问题到可交付代码

> 产品名：**云端 Coding（Daydaymoney）**
>
> 站点：[https://www.daydaymoney.com](https://www.daydaymoney.com)
>
> 源码：
> [https://gitlab.daydaymoney.com/example-user/ram-work](https://gitlab.daydaymoney.com/example-user/ram-work)

软件团队真正耗时的，往往不是「再写一段功能」，而是把线上异常、页面缺陷、接口失败，变成一份可被执行、可追踪、可合并的改动。云端 Coding
把这条链路收成一条产品路径：在真实网页里捕获问题，落到工作面板上的任务，由云端智能体按评论执行，再把结果推回 Git。

它不是又一套看板，也不是只聊天的编程助手。它是一套面向团队的
**AI 云端研发工作台**：任务即工单，评论即指令，容器即执行环境。

---

## 它解决什么问题

今天多数团队的日常是这样的：

1. 产品或测试在浏览器里看到错页面、失败请求、不合理交互。
2. 截图、复制 URL、粘贴请求头，发到即时通讯里。
3. 工程师本地复现、配环境、开分支、改代码、提 PR。
4. 过程中上下文丢失、责任不清、同类问题反复出现。

云端 Coding 把第 1 步到第 4 步接到同一条产品上：

- **捕获发生在现场**：Chrome 扩展可从任意页面选中元素、截取
  Network 请求，或批量收集 5xx。
- **工作发生在工作台**：租户、工作空间、项目、看板任务，权限与进度都有归属。
- **执行发生在云端**：勾选自动运行后，平台按镜像启动云主机，智能体在隔离容器里读评论、改代码、推送远端。
- **结果回到 Git**：与 GitLab SSO、仓库授权、分支策略打通，改动可审查、可合并。

一句话：**看见问题的地方，就能创建可自动执行的研发任务。**

## 一条完整的价值路径

### 1. 在现场捕获，而不是事后回忆

安装浏览器扩展「**云端 Coding: 自动创新助手**」后，有三条入口：

- **页内悬浮球**：在任意网页选工作空间与项目，填写标题和描述；可用指针点选页面元素（含
  Shadow DOM、iframe），把「改成什么样」写进任务。
- **DevTools 面板**：从 Network 里选一条请求，方法、URL、状态码、请求/响应体会自动填入描述。
- **批量错误捕获**：浏览过程中收集失败请求，角标只统计 HTTP
  5xx，可一次批量建任务。

捕获结果对齐工作面板的创建任务字段：进度列、交付物、镜像、智能体资源配置、截止日期、是否自动运行、逐仓基准分支。现场上下文不再靠聊天窗口传话。

### 2. 工作面板：任务是团队的单一事实来源

登录后进入租户控制台。结构是：公司（租户）→ 工作空间 → 项目 → 任务。

工作面板是看板。任务可以关联项目仓库、交付物系统、进度列、协作人。项目上可以配置默认镜像、运行模板（含云主机规格）、是否允许自动运行、Git
仓库与 OAuth。权限按成员、组、角色管理，不是「所有人看见所有东西」。

任务详情里，评论不是附属留言。对自动运行而言，**评论就是给云端智能体的下一条指令**。

### 3. 自动运行：评论驱动云端智能体

当项目允许自动运行，并且已安装可用镜像时，创建任务或后续评论可以启动云端执行：

1. 平台按所选镜像与硬件规格拉起云主机。
2. 容器内智能体读取待处理评论（含自动运行说明、技能、仓库与分支策略）。
3. 克隆已授权仓库（含嵌套仓库策略），按指令改代码。
4. 按配置推送远端、创建 PR；启动日志可在任务详情查看，并归档到对象存储。

工作空间还可以打开 **自动调度**：把自动运行放进时段与槽位队列，而不是每次立刻启服。状态栏能看当前窗口，也能翻调度历史——高峰期不会把机器一次性打满。

Git
授权未齐、镜像未选、架构与实例规格不匹配时，平台会挡住自动运行，而不是默默启一台注定失败的机器。

### 4. 镜像市场：执行环境可安装、可上架

自动运行依赖容器镜像。租户在「镜像市场」浏览、安装可用镜像；已绑定厂商的账号还能看到开发中条目。厂商通过
SSO 进入厂商门户维护镜像组、版本、图标、技能与自动运行说明。

同一套镜像既是「智能体的操作系统」，也是硬件选型的依据：换镜像时要与 CPU
架构、实例规格一致，避免 x86 / ARM 混绑。

  个月存续，到期可续存）、GitLab 磁盘（GB/月）、GitLab 出站流量

- 前端错误带追踪号，便于按一次失败重建整条链路

## 计费怎么理解

平台 **不把「账户里躺着的现金」当产品**。用户购买的是资源配额，使用时扣减配额。

典型商品：

- **任务**：按帖购买，创建任务消耗 1 次，获得 12
  个月存续；到期下架，续存再消耗 1 次配额、不另扣费。
- **GitLab 磁盘**：按 GB/月，面向达到 VIP 门槛的租户。
- **GitLab 流量**：按 GB；同区域内网不计费；须先有磁盘配额。

价格以站点「资源收费标准」页为准，平台保留调价权。下单支付后配额到账。退款与发票按订单与合规流程处理，不在介绍文里替代协议条款。

## 和其他工具差在哪里

| 常见做法 | 云端 Coding |
| --- | --- |
| 聊天窗口里贴截图，工程师再手工建单 | 扩展在页面上把元素、请求、期望写成任务字段 |
| 本地装模型、自己开容器 | 按已安装镜像在云上启服，日志回到任务详情 |
| AI 改完代码在本地，协作靠口头同步 | 任务、评论、PR、配额都在同一租户体系里 |
| 看板与执行环境是两套系统 | 看板任务直接绑定镜像、硬件、Git 与自动运行 |

它不替代 IDE，也不替代 Git 审查。它补的是
**「问题出现之处」到「可合并改动」** 中间那段最容易断的协作。

## 如何开始

1. 打开 [https://www.daydaymoney.com](https://www.daydaymoney.com)，注册并完成邮箱激活。
2. 完成入驻：公司、工作空间、项目；按需要绑定 Git 与安装镜像。

## 写在最后

云端 Coding 的产品判断很明确：AI 写代码已经不难，难的是让
**正确的上下文、正确的权限、正确的机器、正确的仓库**
在同一时刻对齐。把这四件事绑在任务和评论上，团队才谈得上「自动创新」——不是多一个聊天框，而是少一次从浏览器到仓库的上下文丢失。
