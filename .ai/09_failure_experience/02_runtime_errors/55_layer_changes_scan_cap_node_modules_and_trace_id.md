# [运行时] 文件变动「目录扫描已达上限」+ 截断提示缺 data-traceId

## 基本信息

- 版本：1.1.0
- 创建日期：2026-07-19
- 最后修改：2026-07-20
- 维护者：Trae AI 团队

## 现象

- 元素：`[data-testid="task-detail-layer-changes-truncated-hint"]`
- 文案：`目录扫描已达上限，部分文件可能未列入；可刷新重试。`
- 错误/提示节点无 `data-traceId`

## 根因

1. `collectIndex` 全量 walk 工作区，未跳过 `node_modules` 等噪声目录，易触 `MAX_DIFF_ENTRIES=4000`。
2. 截断提示为成功响应的降级态，此前未挂载产生该状态的请求 traceId。

## 解决方案

1. 抽出 `layerParentDiffCollect.mjs`：扫描跳过 `shouldSkipListingDirName` 目录。
2. 前端 `fetch_trace_id` → Hints `:data-traceId`（有则挂、无则省略）。
3. **已落地（OPT-018/019）**：`collectPairChanges` 优先双端 git status + HEAD 分叉 tree-diff；跨仓对象不可见时双端 `ls-tree` 对比；无 git 才 walk。见 `layerParentDiffGit.mjs`。

容器侧改动需镜像发布后生效；前端 traceId 随 SPA collectstatic 生效。

## 线上仍见该提示时的决策树

| 观察 | 含义 | 动作 |
| --- | --- | --- |
| 提示在、节点**无** `data-traceId` | SPA 可能未含 Hints 改动，或 `fetch_trace_id` 未回传 | 硬刷新；确认 `runall-lifecycle.sh build`；查 Gateway 是否透传 trace |
| 提示在、有 `data-traceId` | 容器仍返回 `truncated=true` | 先 Loki 按 trace 查 `diff/parent/files`；确认任务容器镜像 ≥ 含 `layerParentDiffCollect` 的提交（`trae-agent@98a7e3c` 起） |
| 镜像已含跳过噪声后仍截断 | 非噪声文件（源码/生成物）单侧 ≥ `MAX_DIFF_ENTRIES`(4000) | 中期方案：git status / tree-diff 生成变动集，walk 仅作无 git 回退（见意图阶段 C / OPT） |
| 文案是「向下滚动可加载更多」 | 这是分页 `has_more`，**不是**扫描上限 | 勿按本条排障；见 scroll_load_more 意图 |

**勿混淆**：`truncated`（索引扫描触顶）≠ `has_more`（列表分页未完）。同一琥珀节点按 `hasMore` 优先展示续拉文案。
