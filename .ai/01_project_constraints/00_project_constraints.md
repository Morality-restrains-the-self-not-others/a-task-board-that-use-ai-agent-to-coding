# 一、项目规范与约束
1. **目录保护**：禁止改动 `.git` 目录
2. **环境检查**：Django 项目需先确认激活 venv 环境
3. **URL 验证**：项目运行后检查各 URL 响应，确保无 Django 报错
4. **报错处理原则**：碰到报错时，先质疑这个报错的存在是否合理，分析报错原因和上下文，再进行修复
5. **超级管理员创建**：创建超级管理员必须使用 `Saas_project/scripts/init/01_02_create_admin_ruandao.py` 脚本
6. **Git 提交规范**：禁止使用 `--no-verify` 标志提交代码，确保所有测试通过后再进行提交。即使测试失败与当前更改没有关系，也禁止使用 `--no-verify` 标志。当出现测试错误时，应该去修复错误，实在无法修复的错误，应该提示用户处理，然后中断执行。此规则为禁止忽略的核心规则，必须严格遵守。**补充（随机单测遗留债）**：每次提交须执行随机单元测试；若抽测发现遗留失败，适用第 29 条——同次至少修复发现失败集合的 **10%**（向上取整且至少 1 个），余债登记后可继续提交；暂存触及的单测仍须 100% 通过。细则见 [提交时随机单元测试与遗留债 10% 修复](./28_commit_random_unit_test_debt_fix.md)。
7. **降级规则**：在项目使用降级规则时，禁止采用 mock 数据或者模拟数据的方式。与第 16 条的关系见该条末句。
8. **文件修改范围限制**：所有文件修改操作必须限制在项目根目录内，不得修改项目根目录以外的文件
9. **路径配置集中化**：所有路径的设置必须仅在项目根目录的 `paths.conf` 中约定，并使用绝对路径；其他模块需从该文件或项目提供的路径加载模块获取路径。详见 [路径配置规范](./04_paths_configuration.md)
10. **迁移前环境激活**：执行数据库迁移（如 `makemigrations`、`migrate`）前，必须先在仓库根目录执行 `source activate_env.sh` 激活对应环境，禁止在未激活环境下执行迁移命令
11. **架构归一化原则**：涉及 CPU 架构的比较/匹配/存储时，必须先做归一化；在本项目中 **`x86_64` 等价于 `amd64`**（同理 `arm64` 等价于 `aarch64`），禁止直接用原始字符串做等值比较。统一使用 `core.utils.architecture.normalize_architecture` 处理后再比较/去重。
12. **Django 视图实现原则**：Django 项目中禁止使用 ViewSet，应尽可能使用函数式编程实现视图；限制单个函数不超过 100 行，对于超过 100 行的函数必须进行拆分。
13. **函数数量限制原则**：一个文件中存放的函数不能超过7个，在必要的时候，应该进行模块化。
14. **命名一致性原则**：函数、模块、文件、目录的命名应该一致，确保相同意图的函数会分布在同样的路径中。
15. **机器容器 API 访问日志**：[`docs/skills/saas-container/saas-machine-container.md`](../../docs/skills/saas-container/saas-machine-container.md) 所列接口的访问请求日志与敏感字段约定见 [15_container_machine_api_access_logging.md](./15_container_machine_api_access_logging.md)（接口清单以 skill 为准，随 skill 变更维护实现）。
16. **未上线阶段的架构与数据原则（version 未超过 v1.0.0）**：**是否正式上线**以仓库根目录 **`.env_django.yaml`** 中的 **`version`**（语义化版本，如 `0.9.0`、`1.0.0`）为准：**仅当按语义化版本比较 `version` 严格大于 `1.0.0` 时视为已正式上线**；**`version` 未严格大于 `1.0.0`（即未超过 v1.0.0，含 `1.0.0` 及以下）** 时一律按尚未正式上线处理。若本地仅以 `.env_django.json` 注入同名环境变量，则以其中的 **`version`** 键为准（含义与 YAML 顶层键写入 `os.environ` 一致）。在上述尚未正式上线阶段：**不做**面向旧形态的后向兼容处理；**不需要**降级路径或「旧版仍可运行」的保证；**允许**清理不再需要的旧数据；**不需要**为已废弃的文件路径、配置路径或目录约定保留读取或回退逻辑；数据库与 schema **可直接执行**目标形态的迁移（含一次性、破坏性变更），无需为多版本并存设计分阶段兼容迁移。同时 **禁止**将「长期兼容旧形态、双写、渐进迁移、特性开关维持两套逻辑」等作为默认手段；应优先**直接采用目标架构与数据模型**，并通过**清理脏数据、一次性 schema/接口调整、前后端同步改完**等方式落地，避免为未上线阶段堆砌兼容层与迁移分叉。在上述尚未正式上线阶段，**禁止**在默认产品/功能路径上使用 **mock 数据或模拟数据**替代真实数据源与真实接口行为（含用假列表、占位接口、环境开关长期维持「无真实后端」的开发态）；应接入真实服务或与本仓库约定且可审计的本地等价实现。**自动化测试**（单元/集成/Playwright 等）中的 test double、fixture、对外部系统的测试隔离 **不在此限**。**已正式上线**（`version` 严格大于 `1.0.0`）后，再按常规单独评估兼容与迁移策略。**与第 7 条：**第 7 条约束启用降级规则时不得使用 mock；本条约束尚未正式上线阶段产品路径上的 mock；二者场景不同，须同时遵守（未上线且启用降级时，两处均适用）。
17. **支付与 KYC 合规**：涉及收款、付款、充值、提现、订阅、钱包、退款等与资金或支付能力相关的功能，须遵循 [支付与 KYC 合规约束](./16_payment_kyc_compliance.md)（身份层级、数据最小化、审计、第三方与卡数据、AML 挂钩、日志脱敏、测试隔离等）。**微信支付 APIv3 客户端落点**见第 54 条。
18. **异域部署（前端与 API 分域名）**：用户侧 Web 与 API 可处于**不同域名**；鉴权、CORS、Cookie、回调与 E2E 等设计须按跨源场景显式纳入，见 [异域前端与 API 域名分离](./17_cross_domain_frontend_api.md)。
19. **静态资源引用须带内容 Hash 查询参数**：通过 URL 引用且可能被浏览器或网关缓存的前端静态资源（如模板中的 `<script>`/`<link>`、绝对路径动态 `import`、开发态 `/utils/` 等），须在 URL 上附带与**文件内容**绑定的 hash query（如 `?h=<摘要>`），避免命中过期 JS/CSS 导致模块导出缺失等运行时错误；详见 [静态资源缓存击穿（hash query）](./18_static_resource_cache_bust_query.md)。
20. **源代码文件行数上限（500 行）与门禁触发后自动削减**：任意源代码文件（含前端 Vue/JS/TS/JSX/TSX、后端 Python、配置模板等）单文件总行数不得超过 **500 行**。超过此上限、或 pre-commit/CI 行数门禁失败并点名某路径时，视为**行数门禁已触发**：Agent **必须立即自动**将该目标文件（及同次报告中的全部超标文件）通过拆分削减到**目标行数以下**（默认 ≤ 500；以门禁声明上限为准），复跑验收通过后再继续其它功能改动；禁止仅注释「后续拆分」、禁止询问是否拆分、禁止继续向超标文件堆叠。仅当技术框架或外部合约强制要求单文件实现（如某些 GraphQL schema、protobuf 生成文件）时可作为例外，但须在文件头部注释中说明原因与后续计划，且不得借例外继续净增长。此规则优先于任何其他代码组织规则——保证人类的可阅读性，以及智能体的快速检索能力，是项目所有代码的基础质量门槛。细则见 [行数门禁触发后须自动削减目标文件](./27_source_file_line_limit_auto_reduce.md)。
21. **单库 / 单表单服务数据所有权**：任意数据库（或逻辑库）及其中任意数据表，运行时只允许由 **一个拥有服务** 直连访问（读与写均适用）。若多个服务需要同一库/表，须采用 **服务转发**（经拥有服务 API/RPC/领域事件）或 **将数据表迁移出去**（使每张表只归属一个服务），禁止共享连接串、跨服务复用 Model/DAO 或旁路 SQL。详见 [单库/单表单服务数据所有权](./19_single_service_data_ownership.md)。
22. **新增服务 / 接口优先落 Go**：凡新增业务 HTTP/RPC 接口或独立后端服务，默认实现为 **Go**。须先评估并入职责匹配的**现有 Go 服务**；无匹配限界上下文时**新建 Go 服务**。禁止将 Django/Flask 等 Python 进程新增 endpoint 作为默认方案；Python 仅可为可审计例外（须 Go 替代评估与设计门禁）。详见 [新增服务/接口优先落 Go](./20_go_service_first_apis.md)。
23. **已合入 feat 分支与隔离 worktree 自动清理**：Agent / `/10-ship` **默认直接合入 `main` 并 `git push origin main`**（禁止默认 `gh pr create` 后不 merge；ADR-0019）。将 `feat/*` 合入并推送 `main` 后（含内容已在 main、仅 SHA 不同的等价落地），必须删除对应本地与远端同名分支，并拆除 `{repo}-wt/` 与额外元仓 worktree。Agent 在合入推送后须自动执行清理脚本，不得仅口头建议。详见 [已合入 feat 分支自动清理](./21_merged_feat_branch_cleanup.md)；入口 `python3 runAll/scripts/cleanup_stale_worktrees.py --apply --shipped-branch feat/<name>` 然后 `python3 runAll/scripts/delete_merged_feat_branches.py --apply`。
24. **服务监听禁止仅绑 127.0.0.1**：所有 HTTP/TCP 服务 listen/bind 须为 **`0.0.0.0`**（或等价全网卡）；禁止 loopback-only，否则 Docker APISIX（`host.docker.internal`）与边缘 nginx 无法达上游。同机客户端 URL 仍可用 `127.0.0.1`。详见 [服务监听地址禁止仅绑 127.0.0.1](./22_service_listen_host_not_localhost_only.md)；根摘要见仓库根 [`.ai.md`](../../.ai.md)。
25. **应用启动禁止使用环境变量 Proxy**：业务/基础设施进程及其出站 HTTP 客户端**不得**继承或依赖 `HTTP(S)_PROXY` / `ALL_PROXY`；此类环境变量**仅**供开发者本机工具做网络加速。`conf/runAll.yaml` 的 `use_proxy` 须为 `false`；启动脚本应 unset 代理；生产依赖的 Client 应显式直连。详见 [应用启动禁止使用环境变量 Proxy](./23_app_startup_no_env_proxy.md)；根摘要见仓库根 [`.ai.md`](../../.ai.md)。
26. **请求报错展示须带 data-traceId**：凡因网络/HTTP/RPC 请求失败而在前端展示的错误 UI，承载该错误的 DOM 节点（或其稳定可查询的错误容器根）**必须**设置属性 **`data-traceId`**，值为该次失败请求的 traceId（优先响应头 `X-Trace-Id`，其次本端请求头，再次响应体 `trace_id`/`traceId`）；无可用 traceId 时省略属性，禁止伪造。**Agent 排障**：有 `data-traceId` 时须**优先**按该 ID 检索 Loki/Grafana 日志并重建全链路路径，再源码猜测或改代码。详见 [请求报错展示须带 data-traceId](./24_frontend_error_data_trace_id.md)。
27. **会话结束优化建议 Todo**：会话收尾时须将可执行优化建议编号写入 [`.learnings/OPTIMIZATION_TODOS.md`](../../.learnings/OPTIMIZATION_TODOS.md)（`OPT-YYYYMMDD-NNN`，初始 `pending`）；某条落地验证后标记 `completed`。禁止只在聊天中写建议不落盘。详见 [会话结束优化建议 Todo](./25_session_end_optimization_todo.md)。
28. **HTML head 须标明提供页面的服务**：凡本仓库服务对外提供的入口 HTML，`<head>` 须含 `<meta name="trae-service" content="<serviceId>" />`（`content` 优先与 monorepo 顶层目录名一致）。详见 [HTML head 须标明提供页面的服务](./26_frontend_head_trae_service.md)。
29. **提交时随机单元测试与遗留债 10% 修复**：每次 `git commit` 须经 pre-commit 执行 monorepo 随机单元测试门禁；抽测发现遗留失败文件数为 N 时，同次提交至少修复 `max(1, ceil(N×0.10))` 个并复跑通过，余债写入 `.learnings/UNIT_TEST_DEBT.md`；暂存相关单测须 100% 通过；禁止 `--no-verify`。详见 [提交时随机单元测试与遗留债 10% 修复](./28_commit_random_unit_test_debt_fix.md)；门禁 `db/scripts/ci/run_commit_random_unit_tests.py`。
30. **服务仅读本目录配置；跨服务配置须 sync**：业务进程运行时**禁止**直读其它服务的 `conf/<area>/<other-app>/`；需要他方配置时须经本目录 `sync.manifest.yaml` / conf-sync 生成片段，再用 `confload.ReadAppFragment`（或等价仅打开本目录路径的 API）读取。`conf/base.yaml` 寻址模板为唯一约定例外。详见 [服务仅读本目录配置；跨服务配置须 sync](./29_service_own_conf_directory_only_via_sync.md)。
31. **迁移/重构——测试先行**：凡识别到用户指令包含迁移或重构意图（关键词：迁移/migrate、重构/refactor、重写/rewrite、搬迁/relocate、替换/replace、升级/upgrade、抽取/extract、合并/merge、拆分/split；或语义模式如「把 X 移到 Y」「用 Y 重新实现 X」等），Agent 必须在执行代码改动**之前**先建立行为基线——优先扩展现有测试，若无则写 characterization test（基线测试），确保改动前后外部行为一致。迁移/重构完成后须用同一测试集验证通过。不确定时默认触发。排除：修复单 bug、新增独立功能、纯格式化、单文件 < 20 行有效变更且不改接口签名。详见 [迁移/重构——测试先行](./30_migration_refactoring_test_first.md)。
32. **子仓库优先提交**：本仓库为 meta-repo，包含 37 个 git submodule。当一次变更同时涉及子仓库（submodule 目录内）与主仓库时，**必须**先提交并推送每个有变更的子仓库，再提交并推送主仓库。禁止在子仓库未推送的情况下提交/推送主仓库。Agent 在提交前须自动识别有变更的子仓库并确保优先处理。详见 [子仓库优先提交规则](./32_submodule_commit_order.md)。
33. **数据库 ID 字段采用雪花算法生成**：所有**新建数据库表**的主键 `id` 字段**必须**使用 Snowflake（雪花算法）生成，禁止使用数据库自增主键或 UUID。统一参数：epoch=2020-01-01（1577836800000），41 位时间戳 + 10 位机器ID + 12 位序列号。Python 使用 `core.utils.snowflake.generate_snowflake_id()`，Go 复用 `shareLib/snowflake`（`snowflake.GenerateID()` / `snowflake.GenerateIDString()`）。与 [ID 字段字符串传输规范](../03_technical_implementation/11_id_field_string_transit.md) 联合生效（Snowflake 管生成，string 管传输）。存量表迁移时应当切换并触发测试先行规则。详见 [数据库 ID 字段雪花算法生成规范](./35_snowflake_id_generation.md)。
34. **Bug 修复后必须用 Playwright 验收**：凡修复用户可感知的 bug（前端交互、API 响应异常导致的前端错误展示、业务流程断裂等），修复后**必须**编写或扩展 Playwright 端到端测试用例覆盖该 bug 场景，并通过测试验证修复有效且无回归。纯后端/内部服务 bug（不影响用户可见行为）可用单元/集成测试代替，但仍须有自动化测试覆盖。此规则与第 31 条（迁移/重构测试先行）互补：第 31 条管迁移/重构，本条管 bug 修复的回归验收。详见 [Bug 修复 Playwright 验收规范](./36_bug_fix_playwright_acceptance.md)。
36	35. **ORM 优先使用（元规则）**：所有数据库操作**必须优先使用 ORM 库**（Django ORM / GORM），禁止在业务代码中直接编写原始 SQL 语句。CRUD 全部走 ORM 查询构造器；复杂查询优先用 ORM 高级特性（F 表达式、Subquery、CTE、Scopes 等）。原始 SQL 仅限例外场景（Migration DDL、聚合分析、批量操作、数据库专有特性、报表导出、dataMigrate），且**必须**封装在仓储层、使用参数化查询、返回类型安全对象、附带原由注释与测试覆盖。存量裸 SQL 遇功能修改时须同步改为 ORM 或符合封装要求。详见 [ORM 优先使用规范](./37_orm_priority_over_raw_sql.md)。
37	36. **文件修改后格式验证（元规则）**：修改任何文件后，必须使用对应格式验证工具确认文件格式有效。若缺乏验证工具，必须先安装再验证。覆盖 Go（gofmt + go vet）、Python（py_compile + ruff）、JavaScript/TypeScript/Vue（eslint）、YAML（yaml.safe_load + yamllint）、JSON（jq）、Shell（bash -n + shellcheck）、Dockerfile（hadolint）、Markdown（markdownlint）、SQL（sqlfluff）、HTML/CSS（prettier）等全部文件类型。网络不可用时使用语言内建机制（py_compile、bash -n、node --check 等）作为 fallback，并在 commit message 中注明。详见 [文件修改后格式验证](./38_file_format_validation.md)；Cursor：`.cursor/rules/file-format-validation.mdc`（alwaysApply）。
