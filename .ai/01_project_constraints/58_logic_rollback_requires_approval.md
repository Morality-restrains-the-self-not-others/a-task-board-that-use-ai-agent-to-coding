## 背景与动机

改代码时最常见的负债不是「新逻辑写错」，而是**旧逻辑没走**：

- 用新实现替换旧实现后，把旧函数/旧分支「先留着以防万一」
- 测试失败时把部分改动悄悄回退，新旧语义混在同一路径
- 大段注释掉旧代码，而不是删除
- 特性开关长期维持 `if new else old` 两套行为

未上线阶段第 16 条已禁止默认双写/兼容层；本条覆盖**所有阶段、所有语言**：只要出现逻辑回退或旧逻辑残留，就必须先审批，默认动作是**删掉**。

## 什么算逻辑回退

出现任一情况即触发本条（不限于 git revert）：

| 类型 | 示例 |
|---|---|
| 恢复已替换实现 | 从 git 历史拷回已删除函数，与新实现并存 |
| 双路径 | `if useNew { A } else { B }` 且 B 是旧语义；新旧 handler 同时注册 |
| 注释保留 | 注释掉仍可编译的旧函数/旧分支，而不是删除 |
| 兼容名残留 | 新增 `*_old` / `*_legacy` / `*_compat` / `XxxLegacy` 仅因「以后可能要用」 |
| 静默回退 | 为让测试变绿而撤回本会话已采用的目标语义，却不删对应新代码 |
| 无期限开关 | feature flag 同时跑新旧两套，且没有移除日期 |

**不算**逻辑回退（无需本条审批）：

- 纯删除旧代码、只保留一套目标语义
- 修复 bug 时改正当前路径（没有把已废弃路径接回来）
- 测试夹具、test double、characterization 基线（第 31 条）
- 文档中描述「不要这样做」的反例

## 默认动作：删除

Agent / 开发者发现旧逻辑后，**默认删除**旧路径、旧函数、注释块、无引用导出，只留一套可运行语义。删除不需要人类审批。

与第 16 条叠加：`version` 未超过 v1.0.0 时，兼容层/双写/「旧版仍可跑」**几乎总是应删**；审批通过也应写明为何第 16 条不适用。

## 保留旧逻辑 = 必须人类审批

仅当 Agent **认为必须保留或恢复**旧逻辑时，才允许暂停自动化（含 `/goal` 零交互）并征求人类批准。不得把「先留着」当成默认。

### 审批问题（须结构化）

必须说清：

1. **要保留/恢复的是哪段逻辑**（文件、函数、行为）
2. **为什么不能删**（哪条生产路径、哪个外部契约仍依赖）
3. **若批准：移除日期或触发条件**（谁在何时删）
4. **推荐项：删除**（默认选项）

人类选项至少包含：**删除旧逻辑（推荐）** / **批准保留（须标注）**。未得到本会话内明确批准 → **按删除执行**。禁止把沉默、超时、`/goal` 自动推进解释成批准。

### 批准后的落盘

同时满足，缺一不可：

1. 旧逻辑旁注释：`Logic-Rollback-OK: <原因>; remove-by: YYYY-MM-DD`
2. commit message 含一行：`Logic-Rollback-OK: <同一原因>`
3. 原因非空，禁止只写 `ok` / `temp` / `稍后`

```go
// Logic-Rollback-OK: 支付网关仍回调 v1 签名，切换日 2026-09-01; remove-by: 2026-09-01
func verifyV1Callback(sig string) error { ... }
```

## Agent 强制流程

1. **改代码前**：明确目标语义；准备替换则计划删除旧路径，而不是并存。
2. **改代码中**：每切片自检「本切片是否把旧逻辑接回来或留下第二套」。
3. **若只需删除**：直接删，跑测试，继续。
4. **若想保留/恢复**：停笔 → 审批 → 未批则删；已批则写 `Logic-Rollback-OK` 再继续。
5. **禁止**：把旧代码注释掉充删除；禁止「测试红了就回退一半」留下双语义。

本条覆盖 `/goal`「自主决策、零交互」：**删除旧逻辑不询问；保留旧逻辑必须询问。** 支付/安全类闸门同样优先于自动推进。

## 禁止

- 新实现已接管后仍保留可调用的旧函数「备用」
- 大段注释掉的旧实现（版本库里已有历史，不必留在工作树）
- 无 `remove-by` 的双路径 / 兼容开关
- 用 `git revert` / 手工拷回历史来「先恢复再慢慢改」，却不走审批
- 伪造 `Logic-Rollback-OK`（无本会话人类批准）

## 与既有规则的关系

| 规则 | 关系 |
|---|---|
| 第 16 条（未上线不做后向兼容） | 本条的删除默认在未上线阶段几乎总是正确 |
| 第 31 条（迁移/重构测试先行） | 31 保证改前行为有基线；本条保证改后不留第二套 |
| 废弃与迁移技能 | 正式废弃须有替代 + 期限；期限未到也须 `Logic-Rollback-OK` |
| simplify-and-harden | 完成后扫描死代码；发现未审批旧路径按本条删除或补批 |
