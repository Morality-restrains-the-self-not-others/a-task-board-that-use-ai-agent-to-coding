## 规则概述

凡修复用户可感知的 bug，修复后**必须**使用 Playwright 编写或扩展端到端测试用例进行验收，确保修复有效且无回归。

## 触发条件（何时必须用 Playwright 验收）

以下任一情况触发本规则：

1. **前端交互 bug**：按钮无响应、页面渲染异常、样式错乱、表单提交失败等用户可直接观察的问题
2. **API 响应异常导致前端错误展示**：后端错误导致 toast/错误页/空白页等用户可见的异常状态
3. **业务流程断裂**：多步骤操作流程中某一步失败导致用户无法完成目标操作
4. **登录/权限/会话相关 bug**：用户无法登录、权限判断错误、会话过期处理异常等
5. **跨服务协作导致的前端可见错误**：网关超时、服务不可达等在前端表现为错误 UI 的场景

## 例外（可用单元/集成测试代替）

以下场景不强制 Playwright，但**仍须有自动化测试覆盖**：

1. **纯后端内部 bug**：不影响用户可见行为的内部逻辑错误（如日志格式、内部数据转换、metrics 采集等）
2. **纯基础设施 bug**：CI/CD 配置、部署脚本、Docker 编排等无用户界面的问题
3. **第三方 SDK/库调用 bug**：出站调用第三方服务的逻辑错误，可用集成测试 + mock 覆盖
4. **命令行工具/脚本 bug**：无 Web UI 的 CLI 工具或后台脚本

不确定时**默认触发**——优先写 Playwright 测试。

## Playwright 测试要求

### 1. 测试文件位置

- 前端相关：`front_project/app/tests/playwright/` 或对应子目录
- 测试文件命名遵循 `.playwright.test.js` 后缀规范

### 2. 测试内容

- **必须**覆盖 bug 的原始复现场景（修复前失败、修复后通过）
- **必须**覆盖该功能的关键正常路径（防止回归）
- **建议**覆盖边界情况（如有明显的边界条件）

### 3. 测试环境

- 通过 9222 端口 CDP 连接已启动的 Chrome（遵循项目 Playwright 连接规范）
- 测试账号使用项目约定的测试凭证（见 `task2app/测试.ai.md`）
- 本地执行时显示浏览器窗口（`headless: false`），CI 环境自动切换无头

### 4. 验收标准

- Playwright 测试在本机通过
- 测试结果写入 `commitResult/` 对应目录
- 测试脚本退出码正确（通过=0，失败≠0）

### 5. 配套文件

- 测试文件须配套 `${testFileName}.testIntent` 意图文档
- 测试文件须配套 `fileName.sh` 执行脚本

## 与相关规则的联动

| 规则 | 关系 | 说明 |
|------|------|------|
| 第 31 条「迁移/重构——测试先行」 | 互补 | 31 条管迁移/重构场景；本条管 bug 修复场景 |
| 「前端变更 Playwright 验证规则」 | 子集 | 前端变更规则涵盖所有前端修改；本条专门针对 bug 修复，范围更窄但强制力更强 |
| BDD 先测后写规则 | 一致 | bug 修复的 Playwright 测试应在修复代码后立即编写（而非先写测试再修 bug） |
| data-traceId 日志优先规则 | 上游 | 若 bug 附带 `data-traceId`，须先查日志定位根因，再修复并写 Playwright 验收 |

## Agent 执行指引

当 Agent 识别到正在修复 bug 时：

1. **确认 bug 类型**：判断是否属于触发条件（用户可感知）
2. **修复 bug**：完成代码层面的修复
3. **编写 Playwright 测试**：覆盖 bug 场景 + 正常路径
4. **运行测试验证**：确认测试通过（修复有效）且无回归
5. **无法用 Playwright 时**：记录原因，改用单元/集成测试覆盖，并在 commit message 中说明
