# 行数门禁触发后须自动削减目标文件

## 基本信息

- 版本：1.0.0
- 创建日期：2026-07-19
- 最后修改：2026-07-19
- 维护者：Trae AI 团队

## 背景（为何是元规则）

项目已约定单源文件物理行数上限 **500 行**（见 [00_project_constraints.md](./00_project_constraints.md) 第 20 条；前端组件另有 CI/pre-commit 门禁）。实践中 Agent 常在门禁失败后仅口头说明「后续拆分」、继续堆叠功能，或把超标文件标为例外而不削减，导致门禁反复失败、可读性与检索能力持续恶化。

本专文把「**门禁触发 → 立即自动削到阈值以下**」定为禁止忽略的执行义务，与「触及文件时须拆分」叠加适用。

## 规则分类

### 核心规则

#### 行数门禁触发后必须自动削减

- **描述**：一旦判定**行数门禁已触发**（见下方触发条件），Agent **必须在当前会话内、优先于继续堆叠业务功能**，将报告中的**每一个超标目标文件**削减（拆分）到**目标行数以下**（默认 **≤ 500** 物理行；若环境变量/门禁脚本覆盖了阈值，则以该次门禁声明的上限为准），直到复跑门禁通过或手工度量确认不再超标。
- **适用场景**：
  - 任意源代码文件（前端 Vue/JS/TS/JSX/TSX、后端 Python/Go、配置模板等）超过项目行数上限
  - pre-commit / CI 输出 `check_frontend_component_line_limit`（或等价行数门禁）失败
  - Agent 编辑前后自检发现文件已超阈值
  - 用户或日志明确指出某路径「超过 N 行 / 行数门禁」
- **优先级**：高
- **规则类型**：禁止忽略

##### 触发条件（任一即触发）

1. **度量超标**：对目标路径 `wc -l`（或等价）结果 **大于** 当前阈值（默认 500）。
2. **自动化门禁失败**：`task2app/scripts/ci/check_frontend_component_line_limit.py`（`--staged` 或 CI diff）及其它仓库内行数门禁脚本非零退出，且输出点名了文件路径。
3. **显式点名**：用户指令、评审意见、失败经验文档要求处理某超标文件。

##### 强制动作（触发后必须执行）

1. **锁定目标**：从门禁输出或度量结果提取全部超标路径；不得只处理其中一个而留下其它超标文件。
2. **自动削减**：通过职责拆分（子模块 / 子组件 / composable / util / 独立样式模块等）把**每个**目标文件压到阈值以下；允许新增文件承接迁出逻辑，但新建文件同样受 500 行上限约束。
3. **禁止替代动作**（触发后均不算完成）：
   - 仅在头部注释写「后续拆分」或申请例外而不削减（框架/生成物例外见下）
   - 仅收窄本次 diff 的净增长、留下文件仍 > 阈值（CI 遗留容差 `TASK2APP_FRONTEND_LEGACY_GROWTH_GRACE` **不免除** Agent 的削文件义务）
   - 询问用户「是否拆分」或把拆分推到下一会话
   - 继续向超标文件堆叠新功能后再说拆分
4. **验收复跑**：削减后对每个目标文件确认行数 **≤ 阈值**；前端组件须复跑：

   ```bash
   # 仓库根或 task2app 下，按脚本用法
   python3 task2app/scripts/ci/check_frontend_component_line_limit.py --staged
   # 或对触及文件：wc -l <path>  # 须 ≤ 阈值
   ```

5. **同批交付**：削减产生的新文件、import 调整与必要测试须与触发该门禁的改动同批完成，不得留下半拆状态导致构建/测试失败。

##### 阈值与度量

| 项 | 约定 |
| --- | --- |
| 默认上限 | **500** 物理行（含空行与注释） |
| 覆盖 | 门禁脚本环境变量（如 `TASK2APP_FRONTEND_MAX_LINES`）或用户明确指定的更严上限 |
| 「以下」 | 完成后须 **≤ 上限**（等于上限可接受；大于上限不可接受） |
| 度量 | 以仓库内文件实际行数为准，不以「有效代码行」打折 |

##### 例外（窄）

仅当技术框架或外部合约**强制**单文件实现（如部分生成 schema、不可改第三方拷贝）时，可暂缓削减，且须同时满足：

1. 文件头部注释写明原因与后续计划；
2. **不得**在该例外文件上继续净增长功能逻辑（能外提则外提）；
3. 不得把「懒得拆」标成框架例外。

### 最佳实践

- 拆分边界按职责/UI 区域/纯函数工具，避免循环依赖与过深 prop drilling。
- 前端优先抽 composable / 子 `.vue`；后端优先抽模块级函数文件（并遵守单文件函数数量等既有约束）。
- 触及已接近阈值（如 > 400 行）的文件时，宜在同一改动中预防性拆分，避免门禁事后触发。

## Agent 执行要点（摘要）

```
检测到行数门禁触发
  → 列出全部超标目标文件
  → 立即拆分/迁出直至每个文件 ≤ 阈值
  → 复跑门禁或 wc -l 验收
  → 再继续原任务的其余步骤
```
