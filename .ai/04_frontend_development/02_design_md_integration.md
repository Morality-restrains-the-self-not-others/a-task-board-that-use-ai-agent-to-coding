## 规则分类

### 核心规则
> 通过 `DESIGN.md` 建立可执行的统一视觉基线，降低页面风格漂移

#### DESIGN.md 选型与本地化规则
- 描述：在进行页面改版、新页面开发或 UI 大规模重构时，应先选择一个接近目标气质的 `DESIGN.md` 模板，再本地化为项目专用设计基线文件。
- 适用场景：Web 页面设计、组件风格统一、跨页面视觉治理。
- 优先级：高
- 规则：
  - 产品 SPA **默认使用已落地的仓库根 `DESIGN.md`**（紫曜 `#7241F2`）。不要每次任务重新从 catalog 换一套品牌。
  - 仅当用户明确要求新视觉语言时，才从 `awesome-design-md` 选模板（B 端后台优先 Linear / Sentry 一类高密度单强调），再按 `.claude/skills/design-md/references/localize.md` 映射到现有 CSS 变量。
  - 禁止直接照搬外部品牌词汇、专有字体名和文案；颜色角色、字体层级、间距必须映射为本项目命名。
  - 在仓库根目录维护项目级 `DESIGN.md`，作为 AI 代理和开发者统一输入，不在组件内分散描述视觉规范。
  - 对深色/浅色方案、状态色（success/warning/error/info）与可访问性对比度给出明确约束。
  - 门禁：`python3 db/scripts/ci/check_design_md.py`（`colors.primary` 必须等于 `taskFE` `--color-primary`）。

#### 与平台规范协同规则（强制）
- 描述：`DESIGN.md` 定义“风格一致性”，平台设计规范定义“平台合规性”，两者必须同时满足。
- 适用场景：所有前端 UI 任务。
- 优先级：高
- 规则：
  - 先使用 `DESIGN.md` 约束视觉令牌（颜色、字体、圆角、阴影、间距、组件语义）。
  - 再使用 `01_platform_design_skills.md` 对应规范进行可访问性与交互合规审查（Web 至少覆盖 WCAG 2.2 基线）。
  - 发生冲突时：优先保证可访问性和可用性，再回调视觉参数，禁止为追求“像某品牌”而牺牲可读性与可操作性。

#### 页面落地执行规则
- 描述：页面开发需按“前置约束 -> 开发实现 -> 评审回写”的闭环执行，确保规则长期生效。
- 适用场景：新增页面、页面重构、关键组件改造。
- 优先级：高
- 规则：
  - 开发前：加载 `.claude/skills/design-md`，在任务说明中显式声明“本页面遵循项目 `DESIGN.md`”。
  - 开发中：颜色、字号、间距、阴影、圆角优先复用 `DESIGN.md` 中定义的角色，不临时发明样式变量。
  - 开发后：按 `DESIGN.md` + 平台规范进行审查，记录偏差项（如密度过高、对比度不足、层级不清）。
  - 复盘时：将高频偏差回写到 `DESIGN.md` 的 Do/Don't，形成项目内可复用经验。

### 最佳实践
> 提升跨页面一致性和审美稳定性的建议

#### 设计令牌与组件映射实践
- 描述：通过“令牌 -> 组件 -> 页面”三级映射，减少样式重复和视觉漂移。
- 适用场景：中大型 Vue 前端项目。
- 优先级：中
- 建议：
  - 先定义语义令牌（如 `color.primary`, `surface.elevated`, `text.muted`），再映射到按钮/卡片/表单等组件。
  - 保持状态语义一致：同一种状态在不同页面使用同一视觉语义，不重复发明。
  - 关键页面（首页、任务详情、账单页）优先做视觉一致性巡检，作为全局风格锚点。

## 规则冲突处理
- 当规则冲突时，遵循以下优先级：
  1. 核心规则 > 最佳实践 > 风格指南
  2. 文件级规则 > 目录级规则 > 全局规则
  3. 新版本规则覆盖旧版本规则
