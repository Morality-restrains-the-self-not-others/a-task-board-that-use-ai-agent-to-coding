# 二、文档与流程管理
1. **内容梳理**
   - 自动梳理 `页面URL`、`功能描述`、`vue页面` 的对应关系到 `docs/url-page.wsd` 中（抽象术语需替换为具体内容）
   - 自动梳理 `vue页面`、`vue组件`、`组件调用的API端点` 的对应关系到 `docs/{page}-endpoint.wsd` 中，每个页面一个 wsd 文件（抽象术语需替换为具体内容）
2. **流程图生成**
   - 所有业务流程需在 `docs/flows` 目录下生成对应流程图
3. **文件规范**
   - 采用 `.wsd` 格式存储，文件名与用例名称一致
4. **语法检查**
   - 创建 `.wsd` 文件时，使用 PlantUML 进行语法检查
5. **业务流程调整**
   - 对业务流程进行调整时，应先修改对应的业务流程文件，再依据业务流程文件修改代码
6. **测试角色标注**
   - 业务流程中需标注测试用户角色：系统管理员、租户用户、普通用户
7. **业务逻辑调整文档**
   - 当调整业务逻辑时，需要创建对应的 wsd 文件
   - 这些 wsd 文件需要按照金字塔结构放在 docs/flows 目录中
   - 目录名和文件名都应该用中文命名
   - 名称应该加上序号，以便指导查阅顺序
8. **项目功能结构维护**
   - 当增加或调整项目功能时，需要将新增或调整的功能对应的添加到 docs/ProjectFeature.opml 中
   - 确保功能结构与实际代码实现保持一致
   - 按照现有的模块分类和层级结构进行添加或调整
9. **需求对照与变更落地（与元规则 `ai-rules-loader` 中「需求对照与变更留痕」一致）**
  - 执行实现或调整类工作前，先查阅与本功能相关的既有文档：优先 `docs/intents/` 下同名 `.intent.md`、`.test-intent.md`，其次 `docs/flows/`、`docs/ProjectFeature.opml`、`docs/flows/value-stream-test-integration.wsd` 等已记载的范围与测试点。
  - 服务端功能意图文档须含「意图 → 业务事件 → 发布点」对照（或书面无事件例外）；与实现漂移时须同步回写。见 `.ai/08_prompt_management/01_intent_driven_development.md`。
  - 若本轮指令与上述文档中的目标、验收条件、流程或接口约定不一致，视为**需求变更**：在提交改动前，将**变更后的真实需求**写回对应文档（同步更新测试意图、价值流/流程图中受影响的测试点与路径）。
  - 建议在相关意图文档或本节涉及的文档中保留简短**变更记录**（日期、相对上一版改了什么、背景或原因），便于后续会话、评审与审计对照。
