## 规则分类

### 核心规则
> 影响服务端性能和质量的关键规则，必须严格遵守

#### 数据库查询性能

##### N+1 查询规避规范
- 描述：避免 N+1 查询问题，防止在循环中执行重复的数据库查询导致性能急剧下降
- 适用场景：所有涉及 ORM 查询、关联数据获取的服务端代码
- 优先级：高
- 规则：
  - 使用 ORM 时，应优先使用 `select_related()` 预加载外键关联、`prefetch_related()` 预加载反向外键和多对多关联
  - 在循环中访问关联对象前，应确保已通过预加载批量获取数据，而不是在循环内逐个查询
  - 代码审查时检查是否存在「一次主查询 + N 次关联查询」的模式，及时优化
  - 使用 Django Debug Toolbar 或 `django-silk` 等工具定期检测 N+1 问题

##### 原生 SQL SELECT 字段限制规范
- 描述：使用原生 SQL 时，若不需要全部字段，应对 SELECT 进行字段数限制，减少数据传输和内存占用
- 适用场景：所有使用 `raw()`、`extra()`、`cursor.execute()` 或直接拼接 SQL 的代码
- 优先级：高
- 规则：
  - 禁止使用 `SELECT *`，应显式列出所需字段
  - 仅查询业务逻辑真正需要的字段，避免过度获取
  - 对于大表或宽表，尤其要注意只 select 必要列，减少 I/O 和网络传输
  - 使用 ORM 时，可利用 `values()`、`values_list()`、`only()`、`defer()` 等方式限制返回字段

##### 查询字段索引规范
- 描述：查询条件中使用的字段应有对应的数据库索引支持，避免全表扫描导致性能问题
- 适用场景：所有涉及数据库查询的代码开发与表结构设计
- 优先级：高
- 规则：
  - WHERE、ORDER BY、GROUP BY、JOIN 条件中频繁使用的字段，应建立相应索引
  - 新增查询逻辑时，应评估涉及的字段是否已有索引，必要时在迁移中新增索引
  - 复合查询条件应评估是否需要复合索引，注意字段顺序对索引利用的影响
  - 避免在索引列上使用函数或类型转换，以免导致索引失效
  - 定期通过 `EXPLAIN` 或数据库性能分析工具检查慢查询的索引使用情况

## 规则冲突处理
- 当规则冲突时，遵循以下优先级：
  1. 核心规则 > 最佳实践 > 风格指南
  2. 文件级规则 > 目录级规则 > 全局规则
  3. 新版本规则覆盖旧版本规则
