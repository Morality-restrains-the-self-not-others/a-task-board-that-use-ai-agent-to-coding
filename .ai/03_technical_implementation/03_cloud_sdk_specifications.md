## 规则分类

### 核心规则

#### 云厂商SDK调用规范
- 描述：规范云厂商SDK的调用方式
- 适用场景：所有云厂商SDK调用
- 优先级：高
- 规则：
  - 调用云厂商SDK时，必须记录业务Action、AccessKey、RequestId、request和response到日志中
  - 业务Action应清晰描述SDK调用的具体业务操作，便于理解调用目的
  - AccessKey应脱敏处理，仅记录部分信息（如前4位和后4位）
  - RequestId应完整记录，以便于后续问题排查和追踪
  - request应记录完整的请求参数和配置信息，便于重现问题
  - response应记录完整的响应数据，包括成功和失败的情况
  - 日志级别应设置为info，确保在正常运行时也能捕获这些信息
  - 必须将SDK返回的RequestId放入HTTP响应头中返回，使用对应方法名作为RequestId的Key，便于客户端和上层系统追踪
  - 对于云厂商SDK方法调用的返回，应该直接转为JSON，传到前端
  - 调用云厂商SDK时，应该把 request/response 相关的参数输出在返回的响应中，便于前端调试和问题排查
  - 在处理消息队列的消息时如果碰到调用云厂商SDK的方法，应该把requestId、request、response都通过SSE发送到前端，但是前端应该忽略这个消息的处理，主要目的是为了方便排查碰到的相关bug
  - 确保所有云厂商SDK调用都遵循此规范，包括但不限于阿里云、腾讯云、华为云等
  - 阿里云SDK调试方法：当碰到需要调试阿里云SDK调用问题时，可通过日志中的Request ID和 `cloud/providers/aliyun/debug.py` 中的 `debug_aliyun_request` 函数来查找调用SDK方法时的问题，快速判断入参是否一致，以及该请求有什么异常返回
  - **微信支付**不属于云厂商 SDK：必须走仓内 `sdk/wechatpay-go`，见 [59_wechatpay_go_sdk.md](../01_project_constraints/59_wechatpay_go_sdk.md)（ADR-0032）

#### 阿里云SDK使用规范
- 详细内容请参考：[阿里云SDK使用规范](./07_aliyun_sdk_usage.md)
- SDK 源码位于 monorepo `sdk/`（paths.conf：`SDK_ECS_PYTHON` 等）；调用云服务器（ECS）API 时以该目录内 client/models 与 `Saas_project/cloud/providers/aliyun/` 为范例

#### API 重定向处理规范
- 描述：规范API接口的重定向处理方式，确保前后端分离架构的一致性
- 适用场景：所有需要重定向的API接口开发
- 优先级：高
- 规则：
  - API接口禁止返回301/302等HTTP重定向状态码
  - 当需要重定向时，API应返回JSON格式的响应，包含重定向URL信息
  - 前端应用应根据API返回的JSON响应自行处理重定向逻辑
  - 建议的响应格式：`{"redirect_url": "https://example.com/target", "message": "需要重定向到目标页面"}`
  - 确保所有重定向操作都通过前端路由实现，保持前后端职责清晰分离

#### IP端口配置管理
- 描述：规范项目IP端口的配置和管理
- 适用场景：所有项目启动和测试场景
- 优先级：高
- 规则：
  - 配置文件管理：
    - 创建固定的配置文件用于存储IP端口信息
    - 项目启动时自动将使用的IP端口写入配置文件
    - 配置文件格式应统一且易于读取
    - 确保配置文件的安全性和权限控制

  - 测试配置获取：
    - 测试代码必须从固定配置文件中读取IP端口信息
    - 避免在测试代码中硬编码IP端口
    - 确保测试环境与运行环境使用相同的配置管理机制
    - 测试前验证配置文件的存在性和有效性

## 规则冲突处理
- 当规则冲突时，遵循以下优先级：
  1. 核心规则 &gt; 最佳实践 &gt; 风格指南
  2. 文件级规则 &gt; 目录级规则 &gt; 全局规则
  3. 新版本规则覆盖旧版本规则
