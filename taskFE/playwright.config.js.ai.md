## 规则分类

### 核心规则（一级分类）
> 影响代码质量和安全性的关键规则，必须严格遵守

#### 测试配置（二级分类）
##### Cookie 获取优先级规则（三级分类）
- 描述：在进行 Playwright 测试时，应优先从项目中的 `identifier.cookie.json` 文件获取 cookie，只有当该文件不存在或无效时，才进行模拟登录
- 适用场景：所有 Playwright 测试场景，特别是需要身份认证的测试
- 优先级：高

##### 测试平台配置（三级分类）
- 描述：使用 Playwright 测试时应忽略 firefox 平台
- 适用场景：Playwright 测试配置
- 优先级：高

##### 测试超时设置（三级分类）
- 描述：必须为 Playwright 测试设置合理的超时时间，避免无限悬挂
- 适用场景：所有 Playwright 测试
- 优先级：高

##### 有头/无头模式（三级分类）
- 描述：`use.headless` 必须为 `!!process.env.CI`：本地与智能体未设置 `CI` 时显示浏览器；CI 流水线设置 `CI` 时使用无头
- 适用场景：本配置文件维护与执行 Playwright
- 优先级：高

##### 测试文件存放位置规则（三级分类）
- 描述：对于核心测试意图的对应的测试区域如果是某个组件，文件命名应该以`组件名称`.`测试意图`.test.js来命名，存放在 `frontend/tests/e2e/` 目录中
- 适用场景：所有针对特定组件的 Playwright 测试
- 优先级：高

##### API 调用方式规则（三级分类）
- 描述：撰写 Playwright 的端到端测试文件时，API 的调用需要通过点击页面组件进行，禁止直接使用 request 对象发送 API 请求
- 适用场景：所有 Playwright 端到端测试，特别是涉及 API 调用的测试场景
- 优先级：高

### 最佳实践（一级分类）
> 提升开发效率和代码可维护性的建议

#### 测试环境（二级分类）
##### 测试环境启动（三级分类）
- 描述：测试环境的启动必须通过 run.sh 脚本进行
- 适用场景：测试环境搭建
- 优先级：中

### 风格指南（一级分类）
> 统一代码风格和格式的规范

#### 配置文件（二级分类）
##### 配置文件结构（三级分类）
- 描述：Playwright 配置文件应保持清晰的结构，便于维护
- 适用场景：Playwright 配置文件编写
- 优先级：低

## 规则冲突处理
- 当规则冲突时，遵循以下优先级：
  1. 核心规则 > 最佳实践 > 风格指南
  2. 文件级规则 > 目录级规则 > 全局规则
  3. 新版本规则覆盖旧版本规则
