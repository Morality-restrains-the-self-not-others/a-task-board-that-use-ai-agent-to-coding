## OPT-20260727-027 — SQLite→MySQL 迁移完整性验证脚本

- **Status**: pending
- **Created**: 2026-07-27
- **Context**: 2026-07-27 task-bill、task-auth、task-referral 三个服务因 MySQL 数据库存在但迁移文件中残留 SQLite 语法而启动崩溃。根因有三层：
  1. 56 处 `CREATE INDEX IF NOT EXISTS` — MySQL 8.0 不支持（仅 SQLite）
  2. Go 源码 28 处 SQLite 语法：`INSERT OR IGNORE`(8), `datetime('now')`(5), `ON CONFLICT ... DO UPDATE SET`(12), `strftime`(1), `TEXT PRIMARY KEY`(1), `excluded.` 引用(1)
  3. taskReferral `001_referral.sql` 双重 `AUTO_INCREMENT` + `TEXT` 列索引无前缀长度
- **Action**:
  1. 编写 `dataMigrate/check_mysql_compat.py` 扫描脚本，检测所有 SQL 文件和 Go 源码中的 SQLite 专用语法（`CREATE INDEX IF NOT EXISTS`, `INSERT OR REPLACE`, `INSERT OR IGNORE`, `ON CONFLICT`, `datetime('now')`, `strftime`, `TEXT PRIMARY KEY`, `sqlite_master`, `AUTO_INCREMENT.*AUTO_INCREMENT`）
  2. 在 CI pipeline 或 pre-commit hook 中集成此检查
  3. 审计其余 Go 服务（taskEvents, taskCloudService, taskTenantService, taskProjectService 等）的源码是否有同类 SQLite-isms
- **Why**: SQLite→MySQL 迁移已进行多轮手动修复仍遗漏大量语法差异点；自动化检测是唯一可靠的预防手段
- **How to apply**: `python3 dataMigrate/check_mysql_compat.py` 返回非零即阻止提交/部署
