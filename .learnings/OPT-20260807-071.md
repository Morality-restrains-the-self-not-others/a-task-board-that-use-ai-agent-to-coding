# OPT-20260807-071: Git 仓库 OAuth 授权链路修复复盘

**Status**: done
**Created**: 2026-08-07
**Related**: [[opt-20260806-062-sso-jwt-secret-rotation]] [[taskfe-window-apifetch-global]]

## 背景

用户报障：项目页 Git 仓库「重试」→ GitHub OAuth 授权最终失败（`redirect_uri is not associated` → 授权后仍「授权异常」）。全链路排查共六个独立缺陷叠加，全部修复后 e2e 5/5 全绿。

## 根因链（六链式）

### 1. GitHub App 凭据/回调地址（用户侧修复）
- GitHub 侧 callback URL 未注册 `https://daydaymoney.com/redirect/gitsite/github.com/oauth/callback/`；client_id/secret 曾填错。用户已更正。
- conf 两处 SSOT：`conf/auth/git-oauth/providers/http-github-com--app-daydaymoney.yaml` 与 `conf/auth/task-credential/git-oauth-providers/http-github-com.yaml`（sync.sh 从前者拷贝，历史脱节需人工同步）。

### 2. 跨子域会话失效（taskAuth）
- `activate-session` Set-Cookie 无 `Domain` → 只落在 `www.daydaymoney.com`，`daydaymoney.com`（callback 落地域）会话失效。
- 修复：`src/auth_activate_session.go` Set-Cookie 加 `Domain: ssoCookieDomain()`（=.daydaymoney.com），已生效验证。

### 3. APISIX hosts 抢路由 → 前端落地页方案（不改基础设施）
- APISIX `spa-catch-all`（priority 10，hosts [daydaymoney.com, www.daydaymoney.com]）抢占无 hosts 的 `git-oauth-redirect-callbacks`（priority 878）→ `/redirect/gitsite/` 被 SPA 吞掉。
- **按用户方向**：不修 nginx/APISIX，taskFE 新建 `GitSiteOAuthCallbackLanding.vue` 承接 `/redirect/gitsite/:gitsite/oauth/callback/`，解析 gitsite（github.com→github，其余→gitlab）后 `window.location.replace('/api/git-oauth/<provider>-callback/?<完整query>')`（nginx /api 转发）→ 服务端换票。

### 4. provider 配置两处缺陷（taskProjectService）
- 陈旧配置未重启（加载 daydaymoney App）；重启后加载 `github:github-official-daydaymoney`。
- `parseProviderYAML` 的 `case "service":` 误把 `allowedHost:`（公网域名）当 GitoauthBase → access-for-user 走公网被网关 deny-internal 拦截 → `token_error`。
- 修复：`provider_resolver.go` 支持显式 `gitoauth_base:` 字段优先（内网 `http://127.0.0.1:8002`），4 个 provider yaml 加该字段。

### 5. internal 路径契约不匹配（taskGitOauth）
- taskGitOauth 只注册旧路径 `/api/internal/git-oauth/{github,gitlab}-access-for-user/`，调用方（taskProjectService `gitoauth_client.go:53`、taskCredentialService `gitoauth_client.go:66`）用新格式 `/api/internal/{provider}/oauth/access-for-user/` → ServeMux 404（0ms，绕过了 bridge secret 校验所以日志只见 404）。
- 修复：app.go 注册新路径别名（保留旧路径兼容）。

### 6. user_id JSON 精度丢失（taskGitOauth）
- 雪花 ID `873438061961179136` > 2^53：Go `encoding/json` 默认解码为 float64 丢精度 → 按 user_id 精确匹配 SQL 0 行 → `not_found`（access-for-user 返回 not_found → token_error）。
- 修复：新增 `readJSONNumbered`（`decoder.UseNumber()` 保留 json.Number 原文），internal_handlers 5 处 user_id 精确匹配 handler 替换（audit handler 用 optionalInt64 依赖 float64，不动）。
- 注意：JS `Number` 同样是 double——e2e 脚本若以 JS 数字传 user_id 同样丢精度，须传字符串。

### 7. bridge secret 兜底值不一致（三服务）
- taskGitOauth 兜底 `django-insecure-gitOauth-dev-...`（SecretKey），taskProjectService/taskCredentialService 兜底 `task2app-local-sso-bridge-dev-...` → taskGitOauth `requireBridgeSecret` 401。
- 修复（conf SSOT）：新建 `conf/auth/git-oauth/django.yaml`（`ssoJwtSecret` 同源 `conf/core/sso/config.yaml`）；taskProjectService `config.go` 回退链加 conf 键 `gitoauth_bridge_secret`（`conf/taskProjectService/config.yaml`）；taskCredentialService `composition.go` 同加（`conf/container/task-credential-service/config.yaml`）；`conf/runAll.yaml` task-project-service 加 env 段 `TASK2APP_SSO_JWT_SECRET`（runAll 不热加载，本次走 conf 路径生效）。

## 验证

- `validate-git-repos` 返回 `token_status: token_available` / `is_accessible: true`（此前 token_error/not_bound）
- e2e `e2e-tests/git-repo-retry-e2e.js` 5/5 全绿：未授权态「OAuth 授权」→ authorize URL（client_id=新 App、redirect_uri=落地页契约）→ GitHub 授权 → callback code → 落地页 → 换票 → 项目页 `?github=ok` → 徽标「已授权」
- taskGitOauth/taskProjectService/taskCredentialService/taskAuth go test 全绿（taskCredentialService 存量断言 daydaymoney→daydaymoney 已更新）

## 关键契约（后续变更须保持）

- callback URL 白名单：`https://daydaymoney.com/redirect/gitsite/github.com/oauth/callback/`（GitHub App 注册值）
- 换票 redirect_uri 取自 state 签名内值，必须与 GitHub 白名单注册值一致
- internal 路径：`/api/internal/{provider}/oauth/access-for-user/`（新）+ `/api/internal/git-oauth/...`（旧兼容）
- bridge secret SSOT：`conf/core/sso/config.yaml` ssoJwtSecret → `conf/auth/git-oauth/django.yaml` → `gitoauth_bridge_secret` 键 → env 覆盖
- 内网桥接地址：provider yaml `service.gitoauth_base: http://127.0.0.1:8002`（勿用公网域名）
- 雪花 ID 传参：Go int64 精确序列化；跨语言（JS）必须用字符串

**Why**: 六链式叠加导致「授权成功但状态不更新/授权异常」这类疑难问题；本文档固化契约防回归。
**How to apply**: 改动 OAuth 链路（callback/路径/secret/配置）前先对照「关键契约」清单；e2e 回归必跑。
