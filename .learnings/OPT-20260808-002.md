# OPT-20260808-002: 切换工作空间恒 400 修复复盘

**Status**: done
**Created**: 2026-08-08
**Related**: [[taskfe-window-apifetch-global]]

## 背景

用户报障：www.daydaymoney.com work-panel 页切换工作空间失败，页面显示 `p.taskplugin-el-highlight`「切换工作空间失败，请刷新页面重试」（`data-traceid="dbfad899-ac97-4176-809e-410f685e66df"`）。

## TraceId 日志时间线（Loki 本地 3100 命中）

- `task-auth` GET `/api/internal/gateway/forward-auth/` → **200**（鉴权通过）
- `task-project-service` POST `/api/projects/switch/tenant_id/873472655125147648/` → **400**, `duration_ms: 0`（立即拒绝）
- 近 3 天该端点仅 2 条请求（01:20:08 / 01:20:15），**全部 400** → 确定性故障，非偶发

## 根因（两层叠加）

1. **路由错配**：main.go `/api/projects/` 约定式分发中 `case parts[0] == "switch":` 调用 `handleLegacySwitchWorkspace`（main.go:182），而非带 tenantID 的 `handleSwitchWorkspace`。`handleProjectsRoute` 内部虽有正确的 `case "switch"` 分支但**永远不可达**（外层 dispatch 已拦截）。
2. **legacy handler 二次读取 body**：`handleLegacySwitchWorkspace` 先 `readJSONBody` 消费 body → 查 company_id → 设置 `X-Auth-Tenant-Id` → 再委托 `handleSwitchWorkspace`，后者**再次 `readJSONBody`**（body 已排空 → 空 map）→ `workspace_id` 恒为空 → **400 "工作空间ID不能为空"**。`/api/switch-workspace` legacy 路由同样中招（同类恒 400 潜在缺陷）。

## 修复（taskProjectService，commit 见子仓）

- main.go dispatch：`case parts[0] == "switch":` → `handleSwitchWorkspace(w, r, tenantID)`（直达，带说明注释）
- 抽取 `switchWorkspaceCore(w, r, tenantID, userID, wsID)`：body 解析由各入口 handler 完成，核心逻辑只收已解析的 wsID，杜绝二次读 body
- `handleLegacySwitchWorkspace` 同步改为：`requireAuthUser` + 解析一次 body + 委托 `switchWorkspaceCore`（修复其潜藏同类 400）

## 回归测试（Red→Green 已验证）

- `TestSwitchWorkspaceViaConventionRoute`：mux 路由级 `POST /api/projects/switch/tenant_id/t1/` → 200（与生产前端 URL 形态一致；原始代码上精确复现 400）
- `TestLegacySwitchWorkspaceRoute`：mux 路由级 `POST /api/switch-workspace` → 200
- Red 验证：stash 还原原始代码后两测试均以生产同款 400 失败 → 恢复修复后全绿
- taskProjectService 全量 `go test ./src/` 通过（24.6s）

## 遗留建议

- `handleProjectsRoute` 内 `case "switch"` 为不可达死代码（外层 dispatch 已拦截），可后续清理
- 前端 WorkspaceSwitcher.vue 在 `data.success` 分支 `window.location.href` 整页刷新，切换成功后工作空间页数据依赖 workspace_id 参数重载，行为正常无需改动
